# Project agent roles

**D95 default:** use these roles in direct, explicitly assigned sessions under the [issue-driven workflow](../docs/DEVELOPMENT_WORKFLOW.md). The coordinator provides the role, shared contract, issue, immutable base, allowed paths, and checks. Available collaboration tools may run the implementer and independent reviewers; no controller, launcher installation, service, or launch ledger is required. Keep one writer per worktree and at most three implementer sessions at a time besides the coordinator (D97). The loader and CLI setup below are optional legacy execution methods, not bootstrap prerequisites for current work.

These eight roles adapt agency-agents at the exact commit in `sources.lock.json`. Each source Markdown file has a SHA-256 digest; the upstream MIT license is preserved in `LICENSE.upstream`. The adapted prompts use the project's accepted contracts. Upstream UI workflows, default retry counts, deployment permissions, and marketing claims are not execution instructions here.

The retained CLI integration uses explicit prompts in separate `codex exec` sessions. No global roster or `.codex/agents` installation is required. `roles.py list` shows the available roles; `roles.py verify` checks the registry and license. When this optional loader is selected, the coordinator provides its validated JSON handoff, and `roles.py render --role ROLE --handoff FILE` produces the complete prompt with project rules, the shared contract, the role, and a content digest.

The host CLI 0.145.0 was rejected by the server for the owner's configured `gpt-6-astra` model. The project therefore pins Codex 0.167.0 in `toolchain.lock.json`; the model and global installation remain unchanged. Install the project copy with `npm install --prefix .project/cache/codex-0.167.0 --ignore-scripts --no-audit --no-fund --save-exact @openai/codex@0.167.0`. Check the generated package-lock integrity values against the toolchain lock before use. The recorded installation platform is darwin-x64; another runner needs its own verified platform package. The cache is ignored by Git. This follows the [official Codex CLI installation guidance](https://developers.openai.com/codex/cli), with an exact version and a project-local prefix.

Run `python3 .project/agency/probe.py --role reviewer` and the same command with `--role devops` to test the explicit-prompt integration. Both probes use a read-only sandbox, the owner's existing authentication and model, an ephemeral session, and a strict output schema. They compare the actual response with the required role and stage restrictions. CLI exit zero alone does not pass the probe.

Required handoff fields are validated by `roles.py`: task/stage, saved stage limit, authorization reference, run/session IDs, exact base and specification commits, absolute worktree, read-only flag, allowed paths, acceptance criteria, and task text. D93 continues in meaningful blocks without campaign windows while retaining shared invocation history and finite session limits. Historical D92 records keep their original deadline; existing D86 runs retain their BOOT scope. A reviewer receives no writable paths and runs in a separate read-only session. Worker path instructions are not a substitute for the operating-system sandbox or controller ownership checks.

The accepted controller owns process execution, durable state, leases, review, and merges. It validates Git/worktree identity, actual commits, allowed file changes, and evidence itself. Coordinator-managed collaboration turns use the [launch accounting and adoption contract](../automation/launch-handoff.md); these attestations do not assert a provider CLI execution. This role loader only validates and renders instructions; it does not enforce filesystem isolation, run a scheduler, or claim a task is accepted.

Use the installed CLI's `--sandbox read-only` for a reviewer or role probe, and `--sandbox workspace-write` for an authorized writer. Retain managed security settings. Pass the rendered prompt on stdin with `codex exec --json -`; use `--output-schema` for the required response shape. Do not infer readiness from a successful exit. BOOT-02 records a real schema-constrained probe; BOOT-04 separately verifies unattended infrastructure.

Run the role boundary checks with `python3 -m unittest discover -s .project/agency -p 'test_*.py'`. The probe schema is only an installation check; task-result and review schemas belong to BOOT-03. An update to source pins or role text requires review and a new role revision in subsequent handoffs. Existing attempts retain their recorded revision.
