# Работа над extractor

По D84 пользователь разрешил переход к разработке. Реализуется принятое ТЗ: native-данные до подтверждённой доставки в NATS. Прежний запрет реализации D64 отменён; исторические docs-only записи не являются действующим запретом. Код, сборки, runtime-тесты и тестовое окружение разрешены по задачам и gates; production deployment остаётся отдельным действием.

Сначала полный issue backlog, затем BOOT и E01–E07 по зависимостям. Регламент — [DEVELOPMENT_AUTOPILOT](../DEVELOPMENT_AUTOPILOT.md), каталог — [ISSUE_CATALOG](docs/ISSUE_CATALOG.md), GitHub — sigaev-pro/bc-indexer. Никакой issue не считается завершённой только потому, что она описана в ТЗ. Runtime NOT_RUN меняется лишь по реальным evidence.

При начале, возобновлении или передаче работы сначала прочитать [PROJECT_STATUS.md](PROJECT_STATUS.md). Там находятся текущая задача, проверенные результаты и точное следующее действие.

При планировании читать [docs/DECISIONS.md](docs/DECISIONS.md); при исполнении — задачи/dependencies/gates из [docs/DEVELOPMENT_PLAN.md](docs/DEVELOPMENT_PLAN.md) и TASK_DECOMPOSITION. Термины определены в [CONTEXT.md](CONTEXT.md). Каждый worker/reviewer получает эти правила явно, даже если запускается в отдельном worktree.

Перед существенной задачей сохранить её ID и статус в PROJECT_STATUS.md. После ответа пользователя сразу записать решение в docs/DECISIONS.md; после работы сохранить результат, проверки и следующую задачу. Предложения отличать от принятых решений.

После завершения изменений файлов текущего этапа или подэтапа обновить документы состояния, выполнить необходимые проверки и создать Git-коммит со всеми относящимися к работе изменениями. Переходить к следующему этапу или подэтапу только после успешного коммита; это относится и к изменениям одной документации. Проверить результат через git status и сообщить пользователю хеш коммита. При ошибке коммита сохранить текущую точку и устранить причину до перехода дальше. Публикация в remote выполняется по отдельному указанию.

Исходный evm-transaction-extractor-tz-v2.md сохранять без изменений. Рабочая редакция — evm-transaction-extractor-tz-v3-codex.md. Обновлять её по подтверждённым решениям; открытые вопросы оставлять явно открытыми.

Внутри принятых требований технические решения принимаются самостоятельно и фиксируются. Изменение пользовательских гарантий/scope не угадывается: сохранить BLOCKED_DECISION, продолжить независимую разрешённую работу. Агент-исполнитель не принимает собственный результат; необходимы independent review и проверки точного commit. Тестовые retries — D83; orchestration attempts — регламент. Никакого автоматического перехода через непройденный gate.
