# Историческая выгрузка управляется YAML

Актуализация 2026-11-05: это историческое решение. D36 отменил startup history через start_block/reload и default три часа; D38 отложил history/N–M целиком. Текущий live-сбор начинается с H+1 после native sync, настройки применяются перезапуском по [LIVE_CONFIG_SPEC](../LIVE_CONFIG_SPEC.md). [Решения](../DECISIONS.md) имеют приоритет; нижеследующие принятые/открытые варианты описывают только состояние 2026-10-13…15 и не добавляют текущих требований.

2026-10-15 / D20: конкретное управление историей и YAML-reload отложено пользователем для отдельного обсуждения простоты и эффективности. Начальная история и команда N–M приняты; прежние варианты ниже не считать окончательным выбором механики reload.

Пользователь выбрал номер самого раннего блока в YAML как управление глубиной истории: после перечитывания конфига экстрактор сам догружает недостающий диапазон, а live продолжает работать. Если граница не указана, при старте определяется блок за последние три часа; поэтому история организуется как сохраняемое покрытие диапазонов, а не как одноразовая ручная команда backfill.

Конкретная структура полей, поведение сдвига границы вперёд и источники historical state ещё уточняются. Восстановление тем же YAML принято отдельно; его поведение при утрате вычисленной стартовой границы обсуждается в пуле REC, а не подразумевается данным решением.

Уточнение 2026-10-14 (D14/D15): обязательна отдельная команда диапазона N–M без помех live; каждой сети соответствует независимый процесс. Начальная история из YAML сохраняется. Дополняет команда автоматическую догрузку при reload или заменяет её — открытый JOB-01; прежнее решение по reload не отменяется молча и требует согласования перед реализацией.
