## Technical decisions

- **A cmd binary with child processes.** The probe starts a full Bor node
  stack: the lifecycle wiring needs the eth backend. An abandoned node is
  never freed, so each case runs in a child process of its own. The parent
  records a failed child with the end of its error output.
- **The store wrap goes through the node.** A second test-only switch,
  `node.ExtractorWrap`, wraps the one pebble store the eth backend opens.
- **A new OS data directory per start.** The abandoned node holds the lock
  of its data directory, so the new node starts on a new one. The copy puts
  the chaindata files at that node's path. The freezer stays on the OS file
  system and starts empty; the short chain never reaches it.
- **Process-global hooks cleared at each start.** The lifecycle installs
  `rawdb.ExtractorRequire`, `rawdb.ExtractorFinality` and
  `whitelist.ExtractorEnter` as process globals. A new process starts
  without them, so the probe clears them before each start. The restart
  runs in the same child process as the abandoned node, so that node's
  goroutines then run under the new node's hooks. Those hooks fire only at
  the canonical, head and execution writers, and the stack is never
  started; the only background writer seen, the transaction indexer,
  reaches none of them.
- **Copied code.** A portable test compares every copied declaration with
  its source:
  - the inputs, the node start helpers and the export, from the POLY corpus
    probe;
  - the fault store, its batch, the arming table, the catalog order and the
    state reading, from the Geth probe;
  - the decision rows (one row per member), from the BSC probe.

  The storage helpers take the chaindata directory. A portable test pins
  `settleWAL`, `freshFS` and `copyFS` as the BSC probe's with only the
  directory changed. `syncDirs` differs: BSC syncs its fixed path and
  parents, and the Bor helper syncs the directory and every parent up to
  `/`; a portable test pins its text.
- **Unchanged from the Geth and BSC blocks:**
  - the H positions: block 1 for the H points, the genesis for the others;
  - the panic as the fault;
  - the reading of the states below the durable counter.

## Limits

- Part B is open: the six Bor handoffs.
- At the pending points a crash reaches only the power-loss states.
- The model limits of block 0 apply.
- **The store identity preflight does not run.** `borimport.Preflight` reads
  the store from the OS file system, and a new data directory has none, so
  it returns at once. The store identity is still bound inside the store
  (`stateprovider.Bind` in `borimport.Start`).
- **`unsynced_dropped` is an upper bound.** It is the fault store's count of
  writes since the last completed sync. It also counts native writes that
  the abandoned node's background goroutines made between the fault and the
  copy. In run 01, `h.after-boundary-sync` with a power loss counts 5 such
  writes: the native transaction indexer (`core.txIndexer`) wrote the
  transaction index of block 1. A development rerun of that case, with a
  debug build that printed each write after the fault, showed the same
  writes, there after the read of the count. That rerun is not retained as a
  record.
- **The copy is not atomic**, as on BSC. The abandoned node's goroutines
  still run while the probe copies its files one by one, and while the
  power-loss copy follows the reset of the live file system. A write in that
  window would enter the restarted store in either variant; no real crash
  or power loss produces that state. The only writes seen there are the
  native transaction index above (in the unretained debug rerun), which the
  native node writes again. Every state after the restart is one the
  catalog allows.
- **Attempt result vs verdict.** `run.json` `result` records the attempt:
  PASS when the probe ran and the verdict is PASS or INCOMPLETE. qa reads
  the `verdict`.
