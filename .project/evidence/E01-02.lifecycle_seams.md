# E01-02.lifecycle_seams: block 0, lifecycle-core (partial, #18)

This block adds the client-independent core of E01-02.lifecycle_seams. It
contains:

- the caller map of the three accepted native trees;
- the gate that the native patches will use, with its write choke-point check
  and coverage gaps;
- the live boundary H with the gate phases;
- the client-independent finality evidence rules.

The shared `lifecycle` package is copied byte for byte into
`adapters/{geth,bsc,bor}/lifecycle`; the design is in its
[README](../../adapters/geth/lifecycle/README.md), and the architect design
and per-client plan table are in PROJECT_STATUS ("E01-02.lifecycle_seams").

Scope of this evidence:

- Go unit tests on an in-memory store model with injected power loss, using
  the real admission and decision packages;
- portable identity, caller-map and vector checks;
- single-check mutants.

No native client runs here. The native patches that call the gate, the node
wiring and the per-client D100 and D101 items are later blocks. So every
AC-CAP-01-01, AC-LIF-05-02, 05-03, AC-LIF-06-04 and 06-05 profile cell stays
NOT_RUN. This block gives no AC verdict and no public-profile credit. #18

How the map was built:

- **Source review.** The rows come from a read-only source review of each
  tree, done by one reviewer subagent per client. Every `source` function was
  then checked mechanically: it exists in the accepted tree.
- **Which commits.** The trees are the commits of
  `.project/bootstrap/components/candidate-lock.json`, which every merged
  admission and decision patch applies to. The NATIVE_CAPTURE_PROTOCOL table
  names earlier candidates (`9dffe6e9`, `cdb7548b`, `a16f123d`). For BSC that
  is v1.7.8 against the accepted v1.8.2, and the merged BSC patches do not
  apply to `cdb7548b`.
- **Guarded rows are not yet proven.** A GUARDED row cites a merged patch
  edit. It is not a claim that the path is exercised; each client block
  checks its rows against its native tree and exercises them.

Main gaps that the map records as PLANNED. Today each of these bypasses the
decision bridge, or fails closed without a decision:

- **Geth:** `SetCanonical` (the post-merge head path), `writeKnownBlock`,
  `SetHead` rewinds, and `SetFinalized` and `SetSafe`. `SetFinalized` is an
  unbatched, unsynced write that holds no chain lock. `--synctarget` sets
  synthesized finality and is refused.
- **BSC:**
  - `writeKnownBlock` and `SetHead`.
  - Manual database commands such as `removedb` and `db put`.
  - The hash-scheme `Stop` head rewrite.
  - Side branches, which the seam refuses at `Begin`.
  - The accepted tree has no `chainSideFeed`, so the D101 item becomes a check
    that the decided `SIDE` path sends the native `chainBlockFeed` and
    verified-header events.
- **Bor:**
  - `writeKnownBlock`, `SetCanonical`, and the milestone reorganization
    `reorgToFinalized`. The milestone reorganization takes `chainmu` three
    separate times.
  - `SetHead`: its retention check runs before `chainmu`.
  - Milestone and checkpoint whitelist finality.
  - Self-sealed blocks, `removedb` and `purge-whitelisted-entries`.
  - Parallel EVM, which is on by default.

BSC `NotifyFinalized` from the VotePool writes no native state; it is a
READ_ONLY row owned by E05-01.bsc_finality.

`python3 test/harness/lifecycle.py table` prints every row.

## Limits

- **Write from another goroutine.** `Require` catches a write when no pass is
  open, or when the innermost pass belongs to a caller of another effect. A
  write from another goroutine while a pass is open is not caught by the gate.
  It stays a source-review item of each client block.
- **Where `GoLive` is called.** The gate refuses `GoLive` while a pass is
  open and needs the state root of H to be durable. Two things stay client
  block items:
  - that the node wiring calls `GoLive` only after the initial native sync,
    under the guard;
  - where each client reads H and flushes its root.
- **Map completeness.** The map comes from source review and the mechanical
  existence check. Each client block confirms it against native execution and
  AC-CAP-01-01.
