## Limits

- **Storage model.** The power-loss variant drops unsynced data at the Pebble
  level. Torn writes, false syncs and file system metadata loss are not
  modeled. The freezer is not in the model; the short private chains never
  reach it.
- **In-process reopen.** Both variants reopen the node in the same process,
  because the store lives in memory. The Bor block also keeps its
  process-crash model.
- **Report truth.** The judge trusts the probe for the states it reports.
  Each client block must read the `after_restart` states from the durable
  records through the accepted packages, and take `unsynced_dropped` from
  the store.
