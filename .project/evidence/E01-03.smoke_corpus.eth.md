private local ETH slot (chain 31337) and gives the qa verdict per case and
for the family. Every public cell (`ethereum-mainnet`, `ethereum-sepolia`,
`ethereum-hoodi`) stays NOT_RUN (D96). Under D101 this is a short measured
run; no long, load or product run.

## What runs

Design: [test/native_corpus/eth/README.md](../../test/native_corpus/eth/README.md).

1. Build. `corpus_eth.py prepare` starts from the accepted Geth
   decision-bridge preparation of records 03 at `ca88680`:
   `e01-02-decision-geth-preparation-03-ca88680/preparation.json`, SHA-256
   `0c472fa7f1da2818be3dee5881fda08f334bd13634ea8c82f11dd76bcf5fbcb6`. It
   extracts the same Geth `1df30b18` source archive and applies the same
   admission and decision-bridge patch sets. It refuses unless every
   installed patch, file and package equals the accepted install record and
   the repository's Geth adapter code equals the accepted copies. Only the
   probe is added (`cmd/extractor-corpus-eth`). The build uses the accepted
   compiler image and module cache, offline.
2. Generate. Geth's `core.GenerateChainWithGenesis` (ethash faker)
   generates blocks 1 and 2 on the fixture genesis
   (`test/harness/fixtures/genesis.json`: London at genesis, gas limit
   10,000,000, base fee 1 gwei) plus the parent and child contracts.
   Block 1 holds the four corpus transactions of ORACLE.md. Block 2 is
   empty.
3. Import. A new node store is attached with the shipped attach calls:
   `Preflight`, then `AttachDecisions` with `Options{}` and
   `DecisionOptions{}`, the arguments of the `backend_attach_decisions`
   patch. The blockchain config is `core.DefaultConfig()` (hash scheme)
   and the engine is the ethash faker. Both blocks are
   imported with `InsertChain`, through the patched `ProcessBlock` and the
   decided write. The store is then closed, reopened the same way (the
   recovery driver runs), and the same blocks are imported again. Geth skips
   them natively as known blocks before `ProcessBlock`.
4. Export, from native output only: blocks and receipts from `rawdb`; the
   native `callTracer` frames and the native state reads before and after
   each transaction, both from one re-execution of the block on its parent
   state (`core.ApplyTransactionWithEVM`, then the ethash `Finalize`); and
   the state at each block root. Each re-executed receipt must equal the
   imported one in status, gas, cumulative gas, logs and effective price
   (computed from the transaction and base fee, since
   `ApplyTransactionWithEVM` leaves it unset), and the root must equal the
   header root. Bloom and type are compared but derived on both sides, so
   they add no independent check. The driver checks this and also the
   counters and the store continuity across the restart (README, "What the
   probe does"). `decisions` and `reimport` are derived from the retained
   decision and admission records.
5. Compare. `corpus_compare.py expected/eth.json observation.json` (block
   0, unchanged) gives each case PASS, FAIL or NOT_APPLICABLE.

The corpus gives no AC verdict. Its owners take this verdict as an input

What the verdict rests on:
- The state before and after each transaction and the call frames come
  from a native re-execution on the parent state, not from the import
  itself. The
  observation format allows this, and the driver requires the re-execution
  to reproduce the imported receipts and roots. The block-end state is read
  at the imported block root.
- Blocks are sealed by the ethash faker, as in the accepted Geth probes, so
  proof of work is not verified at import.
- The probe calls `AttachDecisions` with the shipped options in-process,
  with `core.DefaultConfig()`; it does not start the `geth` command.
- The re-import is skipped natively as known blocks, so "nothing new after
  the restart" shows that the restart adds no observation or decision and
  leaves the decision records unchanged, not that `ProcessBlock` refuses a
  second decision (the decision-bridge probe covers that refusal).
- Older fork path: the fixture is before the merge (ORACLE.md, "Older fork
  paths"); the current-fork paths go to E01-05.type_paths and E06.
