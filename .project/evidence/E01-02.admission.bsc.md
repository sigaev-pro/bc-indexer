source inputs core on the accepted BSC native import path, adds the BSC
native patch set, and records private local evidence of AC-CAP-02-01 and
AC-CAP-02-02 on the accepted private BSC Parlia fixture. Design:
[native README](../../adapters/bsc/admission/native/README.md).

## Limitations

- **Private fixture.** The fixture has two blocks and one validator. Block
  1 holds the user transfer and the nine Parlia system transactions; block
  2 is empty. The only dependency response is the genesis Parlia snapshot.
- **Power loss.** Native power loss is modeled for the admission and source
  inputs records by the probe store. The drop model loses every unsynced
  write at the SIGKILL; the keep model writes and syncs every record at
  once. Pebble itself loses its unsynced WAL buffer at a SIGKILL, so the
  native model behaves like drop. The native chain data is not under a
  power-loss model. Every crash point is before the native write of block
  2, and the pin ledger syncs its own records.
- **Exec digest.** `exec_digest` is the digest of the native result (block
  hash, state root, receipt root and the receipts' consensus encodings). The
  digest of the immutable record corpus replaces it when the capture side
  (E04) builds the corpus. The consumed-manifest binding of D98 item 7 is
  real: the EXEC_READY record binds the closed manifest that the source
  inputs log produced on the native import path.
- **Engine reset.** Each observation drops the Parlia in-memory snapshots,
  so its reads do not depend on earlier imports. The cost of the snapshot
  walk per block, and a declaration that does not need the reset, are part
  B.
- **Concurrent reads.** While an observation is attached, a Parlia read
  from another goroutine (RPC, miner, vote manager) would be logged into
  the observation and would break replay determinism; replay would then
  fail closed with a prefix conflict. Part B owns this.
- **Caller map.** This block delivers the seam (`SetExtractorHook`),
  `Start`, `Recover` and the guards. Wiring the seam into the node (which
  flag installs it, where the live boundary H is read) and side-chain,
  reorg and known-branch paths belong to E01-02.lifecycle_seams and
  E01-02.decision_bridge.
- **Freezer.** The freezer limit is proven on the real native freezer with
  an ethash-faker chain and a ledger record written directly (the side
  header has no state to pin), not on the BSC fixture, which is far below
  the 90,000-block threshold.
- **Rewind by timestamp.** A rewind by timestamp passes head 0 to the
  guard, so any pinned header refuses it, even if the rewind would keep
  that header.
