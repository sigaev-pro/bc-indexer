## What the records show

Run 03 covers eight scenarios on the private fixture: `live`, `reject`,
`first-handoff`, and the crash points `admitted-synced`,
`admitted-unsynced-drop`, `admitted-unsynced-keep`,
`before-admitted-put-drop` and `exec-ready-unsynced-drop`, each followed by
restart and `Recover`. The driver re-checked every digest and the trace
order with its own rules.

- **AC-CAP-02-01 (no native execution without ADMITTED).** In every
  scenario each block reaches EXEC_READY only after its ADMITTED record and
  pin; the traces show the order. A crash that loses the unsynced ADMITTED
  record (`admitted-unsynced-drop`, `before-admitted-put-drop`) leaves the
  observation of block 2 at INPUT_PREPARING; `Recover` abandons it
  (`abandoned: [2]`) and the next import admits block 2 under a new key
  (`…0002`).
- **AC-CAP-02-02 (ADMITTED is resolved after a crash).** Where ADMITTED
  survives (`admitted-synced`, `admitted-unsynced-keep`,
  `exec-ready-unsynced-drop`), `Recover` re-executes block 2 from its
  capsule and reaches the same EXEC_READY record (digest `78456a0d…`, key
  `…0001`) as the uninterrupted `live` run.
- **Same native result.** `exec_digest` is
  `9dd9a5dd70a25ede17e08eab901a867ccc2b2f4edf542dc670440a7585c3a49d` for
  block 1 and
  `0739ef737afc1136d59c49c0fac77be642aca9e496ddab61dde25ae0d20e74a1` for
  block 2 in every scenario. The consumed manifests are equal too (block 1
  `4fbcd36e…`, block 2 `fb0f9d04…`, one dependency response each), and
  block 1's EXEC_READY digest is `1f89c06e…` everywhere. Capsule digests:
  block 1 `56aff09a…`, block 2 `aad73960…`.
- **NATIVE_REJECTED.** In `reject`, a block 2 whose seal fails is rejected
  by the native Parlia check ("coinbase do not match with signature"); the
  rejection is recorded and the valid block 2 is then admitted under a new
  key.
- **Native deletion is refused under live pins.** The patched `geth` starts
  on the probe home (exit 0). `geth snapshot prune-state`, and a start with a
  leftover state-bloom file (an interrupted prune, which native startup

## Limitations

- **Private fixture.** The fixture has two blocks and one validator. Block
  1 holds the user transfer and the nine Parlia system transactions; block
  2 is empty. The only dependency response is the genesis Parlia snapshot.
- **Blob sidecars.** The fixture is before Cancun and has no blob
  transactions, so its `blob-sidecars` items are empty lists. A unit test
  covers the round trip of a block that carries a sidecar, and the native
  hook test covers the data-availability refusal before `Begin`. No native
  import of a blob-carrying Parlia block is recorded. The native check drops
  the sidecars of a block older than `MinTimeDurationForBlobRequests`, so a
  blob-carrying obligation recovered after that window is stored without its
  sidecars, as any late native import is; `exec_digest` does not cover
  sidecars.
- **Power loss.** Native power loss is modeled for the admission and source
  inputs records by the probe store. The drop model loses every unsynced
  write at the SIGKILL; the keep model writes and syncs every record at
  once. Pebble itself loses its unsynced WAL buffer at a SIGKILL, so the
  native model behaves like drop. The native chain data is not under a
  power-loss model. Every crash point is before the native write of block
  2, and the pin ledger syncs its own records.
- **Exec digest.** `exec_digest` is the digest of the native result (block
  hash, state root, receipt root and the receipts' consensus encodings). The
  digest of the immutable record corpus replaces it when the capture side
  (E04) builds the corpus. The consumed-manifest binding of D98 item 7 is
  real: the EXEC_READY record binds the closed manifest that the source
  inputs log produced on the native import path.
- **Engine reset.** Each observation drops the Parlia in-memory snapshots,
  so its reads do not depend on earlier imports. The cost of the snapshot
  walk per block, and a declaration that does not need the reset, are part
  B.
- **Concurrent reads.** While an observation is attached, a Parlia read
  from another goroutine (RPC, miner, vote manager) would be logged into
  the observation and would break replay determinism; replay would then
  fail closed with a prefix conflict. Part B owns this.
- **Caller map.** This block delivers the seam (`SetExtractorHook`),
  `Start`, `Recover` and the guards. Wiring the seam into the node (which
  flag installs it, where the live boundary H is read) and side-chain,
  reorg and known-branch paths belong to E01-02.lifecycle_seams and
  E01-02.decision_bridge.
- **Freezer.** The freezer limit is proven on the real native freezer with
  an ethash-faker chain and a ledger record written directly (the side
  header has no state to pin), not on the BSC fixture, which is far below
  the 90,000-block threshold.
- **Rewind by timestamp.** A rewind by timestamp passes head 0 to the
  guard, so any pinned header refuses it, even if the rewind would keep
  that header.
