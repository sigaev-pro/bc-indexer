# E01-02.inputs: block 0, inputs-core (partial, #14)

This block adds the client-independent core of E01-02.inputs: the sealed
static input capsule, the append-only consumed-dependency log, the
consumed-manifest digest, and the replay, prefix-conflict and tail-append
rules. The shared package is copied byte for byte into
`adapters/{geth,bsc,bor}/source_inputs`; the design is in its
[README](../../adapters/geth/source_inputs/README.md).

Scope of this evidence: Go unit tests on an in-memory store model with
injected power loss, a portable identity and vector check, and single-check
mutants. No native client runs here. Per-client wiring, the Bor Heimdall stub
and native evidence are later blocks, so every AC-CAP-04-01 to AC-CAP-04-03
profile cell stays NOT_RUN and this block gives no AC credit and no
public-profile credit. #14 stays open.

## What the tests show

Expected digests come from `python3 test/harness/source_inputs.py vectors`,
an independent Python `hashlib` implementation of the README formulas. The Go
test hard-codes them, and `test_source_inputs.py` (run by `bootstrap/ci`)
checks that the Go constants and vector inputs match the Python reference.

The store model makes a write durable only at a sync and, on power loss,
keeps any chosen subset of unsynced writes. The power-loss tests enumerate
every operation index of the step as the crash point and every subset of the
unsynced writes at that point.

| Test | Shows |
|---|---|
| `TestDigestVectors`, `TestEmptyLogFinish` | Capsule, entry, chain and consumed digests equal the independent values |
| `TestCapsulePowerLoss` | A seal interrupted at any point leaves no capsule (a new seal completes it) or the whole capsule |
| `TestReplayReturnsSavedResponseAfterPowerLoss` | Unit-level form of AC-CAP-04-01: after the frontier sync and before the hand-off, a retry returns the saved bytes at the same sequence and never fetches the changed response |
| `TestNextPowerLossAtEveryPoint` | For responses of 0 bytes, 1 byte, one full chunk and three chunks: before the frontier sync the retry fetches the changed response; after it the retry replays the saved bytes; the reopened log stays readable and the final digest equals a clean run of the bytes actually consumed |
| `TestOrphanEntryIsOverwritten` | A complete entry beyond the frontier is never read and a shorter tail overwrites it |
| `TestPrefixConflict` | Unit-level form of AC-CAP-04-02: a different request at a durable offset is `ErrPrefixConflict`, fetch is not called, the store is unchanged and the log stops; a reopened log still replays the prefix |
| `TestTailAppendAndStandInMarker` | Unit-level form of AC-CAP-04-03: the prefix replays, the next request appends beyond the frontier with one fetch, prefix keys keep their bytes, and the final digest bound to a test-only stand-in marker equals the independent value; a closed log refuses new responses and `Finish` needs every durable entry |
| `TestFinishPowerLoss`, `TestFetchErrorWritesNothing`, `TestStoreErrorsStopTheLog`, `TestCorruptRecords` | Interrupted close, source error without writes, fail-closed store errors, and `ErrCorrupt` for damaged manifests, entries, frontier, closed record and chunks |
| `TestKeysStayOutsidePrunedSpace` | No key is 32 or 33 bytes long and every key stays in the observation namespace |

These are unit forms of the three AC scenarios on a store model. The AC
verdicts need native runs with the Bor Heimdall stub (D98) and belong to the
later Bor block and the qa matrix; the real EXEC_READY binding belongs to
E01-02.admission.
