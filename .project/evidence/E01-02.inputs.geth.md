accepted Geth import through a private, test-only probe. PR #138 proved the

## Decisions used here

- Owner decision of 2026-11-10, relayed by the coordinator: the static
  manifest items that the protocol lists and the merged client blocks left
  out are finished inside #14, one session per client.
- Coordinator technical decision (2026-11-10), not an owner answer, which
  follows the protocol text: NATIVE_CAPTURE_PROTOCOL (line 36) puts
  "заранее известные ancestor headers" ("ancestor headers known in
  advance") in the sealed static manifest, and keeps the dependency log for
  responses that are not known before execution. For a Geth block `N`, the
  headers of the BLOCKHASH window, blocks `max(0, N-256)` to `N-1`, are
  known before execution, because they are the ancestors of the imported
  block. They are therefore static capsule items: `parent-header` for block
  `N-1` and `ancestor-header-<n>` for the others. The Geth import of this
  profile has no response that is unknown in advance, so the Geth dependency
  log stays empty and closes with count 0. This replaces the test-only
  routing of BLOCKHASH through the log that PR #138 used; the log mechanics
  stay proven by block 0, BSC and Bor.
- Coordinator technical decision (2026-11-10), not an owner answer: the Geth
  probe sources live in `test/harness/fixtures/source_inputs_geth/`, not in
  `adapters/geth/source_inputs/`. The block 0 check (`source_inputs.py check`
  and `test_source_inputs.py`) compares every file of the three
  `source_inputs` copies, so a Geth-only file there would break
  `bootstrap/ci`. The shared files and the check are unchanged. BSC and Bor
  use `source_inputs_bsc` and `source_inputs_bor`.
- The probe adds one test-only call after `defer evm.Release()` in
  `core/state_processor.go` and a hook file. It is not the product patch:
  under D98, E01-02.admission owns the native patch set and the real
  EXEC_READY binding. The state prefetcher and the parallel processor never
  call the hook; the fixture has no Amsterdam access list, so the serial path
  runs (a lookup outside the hook leaves no lookup event and fails the
  oracle).

## Static manifest of a Geth block

| Protocol item | Capsule item(s) | Native use in the probe | Negative control |
|---|---|---|---|
| Original header | `header-rlp` | The imported block is decoded from it | Oracle test (wrong header); native mutant `block_not_from_capsule` |
| Original body | `body-rlp` | The imported block is decoded from it | `poisoned_body` scenario; oracle test |
| Encodings | `encodings` (JSON naming the format of each encoded item); the encoded items are the exact RLP bytes | — | Oracle test |
| Parent hash and root | `parent-hash`, `parent-root` | — | Oracle tests; native mutant `parent_header_wrong_block` |
| Parent header | `parent-header` | BLOCKHASH(N-1) | `poisoned_parent_header` scenario; oracle tests |
| Ancestor headers known in advance | `ancestor-header-<n>` for the rest of the BLOCKHASH window | BLOCKHASH(n) | `poisoned_ancestor_header` scenario; oracle tests; native mutant `ancestor_window_short` |
| Chain config and fork digest | `chain-config` (JSON of the native config), `fork-id` | — | Oracle tests |
| Native commit | `native-commit` | — | Oracle test |
| Normalization profile | `normalization-profile` (`test-only-probe-v1`) | — | Oracle test |

The oracle checks each item from the saved bytes: Keccak-256 of the headers
against the generated chain, parent links and numbers, the transactions of
the body against the generated transaction hashes, the state root field of
the parent header, the config fields of `genesis.json`, and the fork ID as
the CRC-32 of the genesis hash. `ORACLE.md` lists every check.

#### What the superseded result showed

1. Capsule before execution: in every new seal, exactly one chunk per
   capsule item (eight) was written and synced, then the manifest was written
   and synced, and `OpenLog` synced again before the serial processor
   started block 4. After a SIGKILL right after the seal, a new process found
   the same capsule.
2. Persist before consume: for each fetched BLOCKHASH answer, the events
   between the request and the hand-off are exactly fetch, response chunk,
   entry, sync, frontier, sync, and nothing follows a hand-off before the
   next request. After a SIGKILL between the frontier sync and the hand-off,
   a new process opened the log at frontier 2.
3. Replay uses saved bytes: in `poisoned_log_replay` the saved answers
   differ from native truth, and a replay with the native source handed
   native code the saved answers, which native validation rejected exactly
   as it rejected the control. In the retry and the closed replay, the source
   answers for every durable offset were poisoned, nothing was fetched for
   them, and native validation accepted block 4. The `native_lookup_bypass`,
   `bypass_saved_bytes` and `resolver_never_poisons` mutants show that a probe
   that hands native code anything but the saved bytes, or whose poisoning
   does not work, fails.
