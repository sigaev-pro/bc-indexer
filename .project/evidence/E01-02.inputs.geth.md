# E01-02.inputs: Geth block (partial, #14)

This block runs the shared inputs core of block 0 (PR #137) inside the
accepted Geth import through a private, test-only probe. It proves the ETH
slot of the module output on private local evidence: the static input
capsule is persisted and synced before execution, each consumed native
dependency response is persisted and synced before native code receives it,
and replay after a crash uses the saved bytes.

AC-CAP-04-01 to AC-CAP-04-03 apply to POLY only, so this block issues no AC
verdict and writes no RunManifest. Under D96 and D98, private local evidence
earns no public-profile credit; every public profile cell stays NOT_RUN.
#14 stays open.

## Decisions used here

- Coordinator technical decision (2026-11-10), not an owner answer: the Geth
  probe sources live in `test/harness/fixtures/source_inputs_geth/`, not in
  `adapters/geth/source_inputs/`. The block 0 check (`source_inputs.py check`
  and `test_source_inputs.py`) compares every file of the three
  `source_inputs` copies, so a Geth-only file there would break
  `bootstrap/ci`. The shared files and the check are unchanged. BSC and Bor
  use `source_inputs_bsc` and `source_inputs_bor`.
- Recorded technical decision of this block, not an owner answer: the Geth
  dependency source is the BLOCKHASH ancestor lookup of the serial state
  processor (`core.GetHashFn` through `StateProcessor.Process`). Geth calls
  no external service during import; BLOCKHASH is its native execution
  dependency whose requests depend on execution, so they are not known before
  execution starts and belong in the dependency log, not the static capsule
  (NATIVE_CAPTURE_PROTOCOL, "Admission и source pin"). The request is
  `geth-blockhash-v1 ref=<block hash> number=<n>`; the response is the
  32-byte ancestor hash.
- The probe adds one test-only call after `defer evm.Release()` in
  `core/state_processor.go` and a hook file. It is not the product patch:
  under D98, E01-02.admission owns the native patch set. The state prefetcher
  and the parallel processor never call the hook; the fixture has no
  Amsterdam access list, so the serial path runs (a lookup outside the hook
  would leave the log empty and fail the oracle).

## Design

Files: `test/harness/source_inputs_geth.py` (driver and oracle) and
`test/harness/fixtures/source_inputs_geth/` (`probe.go`, `hook.go.txt`,
`genesis.json`, `expected.json`, `ORACLE.md`, `native_mutants.json`, the
Python mutant table and the portable test). `ORACLE.md` explains every pass
condition.

- Preparation extracts the accepted Geth source, adds the hook call, the hook
  file, the shared `inputs.go` and `inputs_test.go` (as
  `extractor/source_inputs`) and the probe, then runs `go mod verify`,
  `go vet`, the shared unit tests with `-race` inside the native module, and
  `go build`, all offline in the pinned compiler image. It builds one binary
  per native mutant; a mutant that does not compile fails the preparation.
- The probe asserts at compile time that the native `ethdb.Database` satisfies
  the core's `Store`. The core writes into the chain's own on-disk Pebble
  database (with the native freezer) through a recording wrapper that logs
  every `Put` and `SyncKeyValue` in order.
- Chain: genesis plus a reader contract that stores `BLOCKHASH(NUMBER-k)` for
  k = 1, 3, 1. Block 4 calls it, so its log holds three requests (blocks 3,
  1 and 3). Expected answers come from the generated chain, built with a
  separate in-memory chain, not from the import under test. Each attempt is
  a child process; crash attempts end with SIGKILL.
- The oracle recomputes the capsule, entry, chain and consumed-manifest
  digests with the independent Python formulas of `source_inputs.py`.

## What this shows

1. Capsule before execution: in every new seal, all eight item chunks were
   written and synced, then the manifest was written and synced, and
   `OpenLog` synced again before the serial processor started block 4. After
   a SIGKILL right after the seal, a new process found the same capsule.
2. Persist before consume: for each fetched BLOCKHASH answer, the events
   between the request and the hand-off are exactly fetch, response chunk,
   entry, sync, frontier, sync. After a SIGKILL between the frontier sync and
   the hand-off, a new process opened the log at frontier 2.
3. Replay uses saved bytes: in the retry and in the closed replay, the
   source answers for every durable offset were poisoned, no fetch happened
   for them, and native validation accepted block 4 with the expected
   storage. The control shows that native validation rejects poisoned
   answers, and the `bypass_saved_bytes` mutant shows that a probe that hands
   native code the source answer instead of the saved bytes fails.

## Limits

- A SIGKILL is a process crash, not a power loss: the operating system keeps
  unsynced writes. The power-loss model is covered by the block 0 unit tests.
- The hook is test-only. The product native patch belongs to
  E01-02.admission (D98); the real EXEC_READY binding too.
- Ethash faker, private local chain, London rules, serial processor only.
  No prefix-conflict scenario runs natively here; AC-CAP-04-02 is POLY and
  belongs to the Bor block and the qa matrix.
- No AC verdict, no RunManifest, no public-profile credit.
