## Decisions used here

- Owner decision of 2026-11-10, relayed by the coordinator: the static
  manifest items that the protocol lists and the merged client blocks left
  out are finished inside #14, one session per client.
- Coordinator technical decision (2026-11-10), not an owner answer, which
  follows the protocol text: NATIVE_CAPTURE_PROTOCOL (line 36) puts
  "заранее известные ancestor headers" ("ancestor headers known in
  advance") in the sealed static manifest, and keeps the dependency log for
  responses that are not known before execution. For a Geth block `N`, the
  headers of the BLOCKHASH window, blocks `max(0, N-256)` to `N-1`, are
  known before execution, because they are the ancestors of the imported
  block. They are therefore static capsule items: `parent-header` for block
  `N-1` and `ancestor-header-<n>` for the others. The Geth import of this
  profile has no response that is unknown in advance, so the Geth dependency
  log stays empty and closes with count 0. This replaces the test-only
  routing of BLOCKHASH through the log that PR #138 used; the log mechanics
  stay proven by block 0, BSC and Bor.
- Coordinator technical decision (2026-11-10), not an owner answer: the Geth
  probe sources live in `test/harness/fixtures/source_inputs_geth/`, not in
  `adapters/geth/source_inputs/`. The block 0 check (`source_inputs.py check`
  and `test_source_inputs.py`) compares every file of the three
  `source_inputs` copies, so a Geth-only file there would break
  `bootstrap/ci`. The shared files and the check are unchanged. BSC and Bor
  use `source_inputs_bsc` and `source_inputs_bor`.
- The probe adds one test-only call after `defer evm.Release()` in
  `core/state_processor.go` and a hook file. It is not the product patch:
  under D98, E01-02.admission owns the native patch set and the real
  EXEC_READY binding. The state prefetcher and the parallel processor never
  call the hook; the fixture has no Amsterdam access list, so the serial path
  runs (a lookup outside the hook leaves no lookup event and fails the
  oracle).

the CRC-32 of the genesis hash. `ORACLE.md` lists every check.

## What this shows

1. Every static item of the protocol list is in the Geth capsule, sealed and
   synced before execution: in every new seal, one chunk per item (13) was
   written and synced, then the manifest was written and synced, and
   `OpenLog` synced again before block 4 started.
2. The saved bytes are what native code uses: the block is decoded from the
   saved header and body, and each BLOCKHASH answer is the Keccak-256 of a
   saved header. A poisoned parent header, ancestor header or body in the
   capsule makes native validation reject the block, and a retry with the
   native source still uses the saved poisoned bytes and is rejected again.
3. A retry never asks the source: after a SIGKILL right after the seal and
   after a rewind, the retry used the saved capsule although its source
   would have poisoned three items.

## Limits

- A SIGKILL is a process crash, not a power loss: the operating system keeps
  unsynced writes. The power-loss model is covered by the block 0 unit tests.
- The hook is test-only. The product native patch and the real EXEC_READY
  binding belong to E01-02.admission (D98).
- The window is exercised at block 4 only, where it starts at the genesis; a
  full window of 256 headers is not run. The normalization profile is a
  stand-in ID (`test-only-probe-v1`) until the normalizer defines a product
  profile.
- With an empty Geth log, this block no longer exercises the dependency log
  natively for Geth; the log mechanics are proven by block 0 and natively by
  the BSC and Bor blocks.
- Ethash faker, private local chain, London rules, serial processor only.
- No AC verdict, no RunManifest, no public-profile credit.
