## Technical decisions

These are recorded here as technical decisions within the card, not as owner
answers. Both reviewers found each one justified.

1. **Known-block activation is exercised through a direct hook.** On a
   capture node, no native entry reaches `writeKnownBlock`, for two reasons.
   The admission inserts one block per batch. The native left-trim of
   `insertChain` (`core/blockchain.go`, the first known-block loop) replaces
   the known-block error with the fork-choice result. So a stored side block
   that needs a reorganization is executed again under a new observation,
   and the import path decides it (captured). The patched `writeKnownBlock`
   is one CANONICAL decision of `bor.known-block`. The probe reaches it
   through `core.ExtractorWriteKnownBlock` (test only), which holds `chainmu`
   as `insertChain` does.
2. **The milestone reorganization is a rewind decision, then import and
   set-canonical decisions, under one chain lock.** The plan row reads "as
   one decision or fail closed". The native rewind deletes every block above
   `rewindTo`, side blocks too, so the canonical chain is executed again.
   Those executions take the guard in their own observations, so they cannot
   sit inside one decision that holds the guard. The capture path runs the
   whole sequence under one `chainmu` hold, so no other caller runs between
   the steps, and each head step is decided. The probe reaches it through
   `eth.ExtractorReorgToFinalized` (test only), which calls the patched
   native `reorgToFinalized`.
3. **Lifecycle markers are written in a batch of their own.** The startup
   reconcile settles an unresolved lifecycle intent from native evidence. It
   resolves the intent, rejects it, or completes a multi-block mutation that
   a loss interrupted. NATIVE_CAPTURE_PROTOCOL allows completion from the
   intent, rejection, or a source invariant error.
4. **The startup reconcile compares the head only.** It does not decide a
   native finality write made at startup before the gate opens (the
   whitelist `NewService` rewrite of a corrupt lock record). The Bor
   finalized hash is set only by the refused Engine API. Owner of typed
   finality evidence: E05-01.polygon_observer.
