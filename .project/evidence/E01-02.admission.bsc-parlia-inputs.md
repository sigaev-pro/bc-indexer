## How each plan row is met

- **Reads below the window.** Header verification, `Process`, `Finalize`
  and BLOCKHASH read headers through the observation's reader (patch 01).
  The reader serves only the capsule headers: the parent and the 256
  BLOCKHASH ancestors. Any other header read stops the observation, which
  stays ADMITTED (fail closed).
  - `FindAncientHeader` runs inside the Parlia snapshot lookup, which is a
    logged dependency response (next row), so its header reads are native
    and never observation reads.
  - `GetFinalizedHeader` and the fork choice run after EXEC_READY. They do
    not feed the execution result; the finality decision belongs to
    E01-02.decision_bridge.
- **Snapshots, read order, fresh engine.** Parlia gets each snapshot as a
  logged response: the request is the number and hash, the response is the
  snapshot's JSON, and the response is durable before Parlia receives it.
  - A retry receives the saved bytes.
  - Only capsule headers may be requested, and a repeated request in one
    observation receives the first response.
  - The engine reset of part A is gone. The warm and cold imports of the
    long chain log the same bytes.
  - The order is the native order: one block per `insertChain`, header
    verification before execution, and serialized requests. Readers on
    other goroutines keep the native chain, except through the shared
    `SystemCallBackend`: while an observation is attached, a call on
    another block from another goroutine is refused and stops the
    observation, and a call by number is always refused.
- **System-contract calls.** They run in `Finalize` on the parent state, by
  the parent hash. `SystemCallBackend` serves them:
  - It refuses any other block while an observation is attached.
  - It runs without the import tracer.
  - `Start` refuses an engine without `ethAPI`.
  - A failed call is marked `ErrExtractorSystemCall` and keeps the
    obligation ADMITTED.
- **Parent state.** `CheckParentState`, which walked the whole state, is
  replaced by a check at the point of read:
  - A state read error during execution is marked
    `ErrExtractorParentState` (patch 01), and `Validated` refuses a result
    read with an error.
  - The obligation stays ADMITTED, and a retry with the state present
    resolves it.
- **Window and checkpoint rule.** The capsule holds the parent and the 256
  BLOCKHASH ancestors, and declares the snapshot rule (`parlia-snapshots`).
  A stored checkpoint snapshot is read inside the native lookup, so
  checkpoints do not widen the window. The long chain proves the rule on the
  real import path:
  - a stored checkpoint snapshot at 1024;
  - block 1030's window, 1029 down to 774, which lies below that checkpoint;
  - the same results from a warm and a cold engine.

## Limitations

- **Private fixtures.** The two-block fixture of part A has one validator.
  The long chain has 1,030 blocks with the same validator, so these do not
  occur:
  - vote attestations (no vote pool);
  - a validator-set switch with a lookback;
  - Bohr turn-length calls, Feynman breathe blocks, Lorentz and Maxwell
    epoch changes, and blob blocks.

  They all run inside the logged snapshot lookup or in `Finalize` on the
  parent state, so the rule covers them. Their native exercise is on the
  public profiles (E06, E07).
- **Trusted-checkpoint path.** `snapshot` takes it only after a walk of
  more than 600,000 headers (`params.FullImmutabilityThreshold`) without a
  stored checkpoint. The trusted run exercises it natively on a private
  chain of one validator, with the stored snapshots deleted and the startup
  head verification defeated. On mainnet a node rarely takes it, and only
  on a cold start without stored snapshots.
- **Not executed on the fixtures.** The blocks are empty, so BLOCKHASH is
  never executed on the BSC import path; the full BLOCKHASH window is
  proven by the Geth block. The Bohr turn-length and Feynman breathe-block
  call marks (patch 06) are checked by source review only.
- **Snapshot bytes.** Only retries are byte-stable: a retry receives the
  saved bytes. The trusted-checkpoint path builds its snapshot with empty
  recents, so its bytes can differ from a lookup that starts at a stored
  checkpoint. The long chain checks the stored checkpoint at 1024 only by
  its result; a cold lookup from the genesis would give the same bytes.
- **Undeclared header reads.** No undeclared read occurs on the fixtures.
  The reader's refusals are covered by unit tests and by the native
  hook-contract case `reader-in-verify`.
- **Node wiring.** The node must give Parlia an `ethAPI` over
  `SystemCallBackend`, not the RPC backend. That wiring belongs to
  E01-02.lifecycle_seams.
- **Repeated work.** The native snapshot lookup runs once per snapshot per
  observation. Its cost on mainnet, a walk from the stored checkpoint, is
  the native cost.
