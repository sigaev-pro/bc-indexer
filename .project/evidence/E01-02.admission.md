# E01-02.admission: block 0, admission-core (partial, #16)

This block adds the client-independent core of E01-02.admission: the
guard/pin/ADMITTED seam, the EXEC_READY record bound to the closed
consumed-input manifest of E01-02.inputs (D98 item 7), the NATIVE_REJECTED
and ABANDONED exits, and the shared canonical JSON rule (D99 item 3). The
shared package is copied byte for byte into `adapters/{geth,bsc,bor}/admission`;
the design is in its [README](../../adapters/geth/admission/README.md). The
block also adds `Log.Closed` to the shared `source_inputs` package.

Scope of this evidence: Go unit tests on an in-memory store model with
injected power loss, an end-to-end binding test with the real `source_inputs`
log, a portable identity and vector check, and single-check mutants. No
native client runs here. Native wiring, the retention and safe-point patches
and the per-client evidence are later blocks (plan in PROJECT_STATUS), so
every AC-CAP-02-01 and AC-CAP-02-02 profile cell stays NOT_RUN. This block
gives no AC verdict and no public-profile credit. #16 stays open.

## What the tests show

Expected digests and canonical outputs come from
`python3 test/harness/admission.py vectors`, an independent Python
implementation (`hashlib` and `json`) of the README formulas, saved as
`vectors.json`. `test_admission.py` (run by `bootstrap/ci`) checks that the
file matches the Python output, that the consumed-digest formula and tag equal
those of `source_inputs`, and that the binding test uses the `source_inputs`
vector inputs.

The store model makes a write durable only at a sync and, on power loss,
keeps a chosen subset of unsynced writes.

| Test | Shows |
|---|---|
| `TestDigestVectors`, `TestFullFlow` | Observation key and the ADMITTED, consumed and EXEC_READY digests equal the independent values; every key is longer than 33 bytes and under the producer prefix |
| `TestBeginPowerLoss` | A Begin interrupted at any point leaves no observation or INPUT_PREPARING, never a counter without its record; the next sequence is consistent |
| `TestAdmitPowerLoss` | Unit form of AC-CAP-02-01 and AC-CAP-02-02: before the closing sync returns, a power loss leaves INPUT_PREPARING (abandoned, pin released) or a complete ADMITTED record, never EXEC_READY; after it, the same record is recovered, `GoLive` is refused, the pin is not released, and `ExecReady` in RECOVERY_ONLY completes the same obligation |
| `TestExecReadyPowerLoss`, `TestAbandonPowerLoss`, `TestRejectPowerLoss` | Each step either completes or reopens in the earlier state, and a retry completes it with the same record |
| `TestExecReadyBinding` | EXEC_READY is refused (and nothing is written) if the log is not closed, names another observation or capsule, has a digest that does not recompute, or if the pin or capsule changed |
| `TestRejectClosesAnAdmittedObservation` | A validation failure after ADMITTED is closed as NATIVE_REJECTED in RECOVERY_ONLY, the pin is released and new admissions resume |
| `TestOpenRejectsCorruptRecords`, `TestBeginRefusesRecordBeyondCounter` | Every damaged, missing or contradictory record is `ErrCorrupt` |
| `TestModesAndPending`, `TestOneAdmissionPerProducer`, `TestGuard` | Mode rules, the counter re-read against a second instance, and the guard token rules (nil, released, foreign, stale; blocking while held) |
| `TestStoreErrorsStopTheAdmission`, `TestOpenChecksArgumentsAndStoreErrors` | Store and release errors stop the admission; read errors pass through |
| `TestCanonicalVectors`, `TestCanonicalDepthLimit`, `TestCanonicalRefusalReasons` | Go output equals the Python output for 39 cases (accepted and refused), output is stable, depth 64 is accepted and 65 refused |
| `TestRealBinding` (binding) | With the real `source_inputs` log, EXEC_READY is refused before `Finish` and then binds the independent consumed digest of the `source_inputs` vectors (D98 item 7) |
| `TestPowerLossAtEveryStep` (binding) | A power loss at every store operation from Begin to EXEC_READY, with four subsets of unsynced writes kept: INPUT_PREPARING is abandoned and a fresh observation completes; an ADMITTED obligation is completed in RECOVERY_ONLY, fetches only the responses that were not durable, and its EXEC_READY equals the clean run |
