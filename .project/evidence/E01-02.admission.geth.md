# E01-02.admission: Geth block (partial, #16)

This block wires the shared admission core of block 0 (PR #146) into the
accepted Geth import path and adds the Geth native patch set that
E01-02.admission owns under D98 and D99: the product import path with the
per-block observations, `Reject` on native validation failure, the retention
patch (D98 item 2), the VM safe-point patch (D98 item 4), the pin adapter,
the recovery driver, the startup identity, the shared canonical JSON form of
the genesis and config capsule items (D99 item 3) and the full 256-header
BLOCKHASH window (D99 item 5). The design is in
[adapters/geth/admission/native/README.md](../../adapters/geth/admission/native/README.md);
the oracle is described in
[ORACLE.md](../../test/harness/fixtures/admission_geth/ORACLE.md).

AC-CAP-02-01 and AC-CAP-02-02 are proven here for the private local ETH slot
only, by measured run 03 below. Under D96, D98 and D99, private local evidence earns no public-profile
credit: every public AC-CAP-02 cell stays NOT_RUN for E06 and E07, and this
block writes no RunManifest. #16 stays open until the BSC and Bor blocks are
accepted.

The removedb block (D100 item 3, PR #154) adds the manual database guard
below. Its records 05 repeat every scenario of the Geth block on the new
patch set, so AC-CAP-02-01 and AC-CAP-02-02 also pass at `b9fc992`.

## Decisions used here

- D98 items 2, 4 and 7 and D99 items 3 and 5 assign the retention patch, the
  safe-point patch, the real EXEC_READY binding, the canonical JSON rule and
  the window rule to E01-02.admission; the plan table in PROJECT_STATUS
  ("E01-02.admission") splits them per client.
- Coordinator technical decision (2026-11-10, #14): the BLOCKHASH window
  headers of a Geth block are static capsule items, and the Geth dependency
  log closes with count 0. This block keeps that rule; the EXEC_READY record
  still binds the closed consumed manifest.
- Owner split of #16 (2026-11-11): block 0, then one block per client in
  parallel sessions. Geth-only files live in `adapters/geth/admission/native/`
  and `test/harness/fixtures/admission_geth/`; the shared `admission` and
  `source_inputs` copies are unchanged.

## What this shows

For the private local ETH slot, on the patched Geth import path:

1. AC-CAP-02-01: a power loss before the closing ADMITTED sync leaves no
   accepted obligation and no EXEC_READY; the observation is abandoned with
   its pin, and only a new observation of the same block reaches EXEC_READY.
2. AC-CAP-02-02: after a power loss right after the ADMITTED sync, the same
   obligation (same candidate, pin digest and capsule digest) is completed
   from its pin and capsule; while it is open, a new H and the LIVE switch
   are refused, and a changed static input stops recovery instead of binding
   a different capsule.
3. A native validation failure ends the observation as NATIVE_REJECTED,
   live and in recovery, and never as EXEC_READY.
4. The retention guards run in the shipped binary and the native code
   paths: offline pruning, an interrupted prune at startup, a requested
   rewind and the chain freezer all refuse to delete pinned data. A capture
   store never imports without its admission: a start without the config
   and `geth import` are refused. Since the removedb block (records 05), no
   manual `geth` command deletes or rewrites chaindata while a pin is live
   or an obligation is open, the refused command leaves the store byte for
   byte unchanged, and recovery still completes afterwards.
5. The full 256-header BLOCKHASH window is a static capsule item set, and
   native execution reads it from the saved headers.
6. The interpreter calls the owned capture safe point once per admitted
   execution, and the prefetcher and the stateless self-check never reach it.

## Limits

- A SIGKILL is a process crash. The probe writes the admission records, the
  capsule and the log through a power-loss store model that keeps writes in
  process memory until `SyncKeyValue`, so a kill before a sync loses every
  unsynced extractor write, one subset that a power loss may keep. Native
  chain data and the pin ledger are written to the native store directly and
  keep process-crash semantics; the block 0 unit tests cover every subset of
  unsynced extractor writes.
- Ethash faker, private local chain, London rules, serial processor. The
  parallel processor is turned off for admitted blocks because it reads
  neither the saved BLOCKHASH answers nor the safe point.
- The execution digest is `ExecResultDigest` (block hash, gas used and
  receipts) until the capture side computes the record corpus digest.
- The normalization profile is the stand-in ID `test-only-probe-v1`
  (D99 item 4, E04-01.block_record).
- The patched `geth` command is built with a plain `go build -trimpath` of
  `./cmd/geth` with the accepted compiler and module cache, not with the
  release build script of E01-01.builds.
- Startup repair rewinds keep native behavior (see the README limits).
  Since the removedb block, the manual database commands are guarded; the
  guard opens the store with the `--datadir.ancient` flag, and a failed
  read-only open refuses the command.
- No AC verdict for public profiles, no RunManifest, no public-profile credit.
