## Reviews

Review 001 (head `b58d33a`, records 01): Spec REQUEST_CHANGES and Standards
REQUEST_CHANGES, from separate read-only subagents. The follow-up commit
fixes them:

- Spec P1: the known-branch walk trusted the canonical-hash index, which can
  outlive a head rewind, so a forkchoice forward after a startup rewind could
  activate blocks with no corpus. The branch is now every block above the
  common ancestor with the current head, found from the headers.
- Standards P1: recovery wrote the view with the native finality references
  (after a restart safe equals finalized), so a completed lifecycle intent
  or a reconciliation step could absorb a safe change without a decision.
  Every view write during recovery now keeps the stored references and
  changes only the head or the decided field; a new crash scenario (SetHead
  with safe A5 and finalized A3) shows the safe reset decided after the
  completion.
- Spec P2: a crash inside the reorganization of a lifecycle CANONICAL
  decision stopped the next start. It is now completed from the old head
  through `ExtractorCompleteHead` (crash scenario `reorg`).
- Spec P2: the missing targeted replay had no owner. The README now states
  why the protocol's source error applies (the inputs of a closed
  observation are purged) and names the liveness effect; an owner is
  proposed (E05-01.activation_gc) for the coordinator to confirm.
- Standards P2: the finality setters moved the in-memory reference before
  the batch was durable; the batch is now written and synced first, and a
  failed write is fatal. A failed `GoLive` on a first start now stops the
  node instead of leaving it uncaptured.
- P3: a reconciliation batch failure no longer counts as a native
  rejection; `CheckFlags` checks `--syncmode` only when set (`eth.New`
  checks the final mode); the side-chain route text; FINALITY decisions are
  now checked by field, caller and references; new driver tests and mutants
  for the bootstrap live checks and the crash restart error; the release
  build stamp of the native commit is recorded as an E01-01.builds and E06
  item (D100).

## Limits

See the native README, "Limits". In short: hash state scheme only; no
targeted replay for a branch block without corpus (source error instead);
a partial SetHead rewind interrupted before its marker stops the next start
(E01-04.early_faults); a refused finality setter logs and writes nothing
while the Engine API still answers VALID; typed finality, regression and GC
anchor rows are E05-01.eth_finality.
