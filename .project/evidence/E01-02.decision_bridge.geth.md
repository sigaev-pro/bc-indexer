## What this block changes in Geth

Six patches of `adapters/geth/decision/native/patches.json`, applied after
the 23 admission patches, and the new file `core/extractor_decision.go`:

| Boundary | Change |
|---|---|
| `ProcessBlock` write section | After EXEC_READY, an observed write is one native decision; before the bridge opens (admission recovery) the block is not written |
| `writeBlockWithState` | StateDB commit, child-root barrier (`triedb.Commit(root)`, `SyncKeyValue`), `Intend`, then the block batch; a `SIDE` decision (`InsertBlockWithoutSetHead`) carries its marker there |
| `writeHeadBlock` | Only the head batch of the decided block carries the marker, then `SyncKeyValue`; the head batches that `reorg` writes for lower blocks carry none |
| `ProcessBlock` after the write | `Resolve`, then `Cleanup` |
| `eth/backend.go` | `AttachDecisions`: `OpenWithCleanup` with a `source_inputs.Purge` adapter, the recovery driver, `decision.Bridge.GoLive` |

The recovery driver settles an unresolved intent from native evidence (the
marker; a Geth bad block that is not stored; a block stored with its state,
completed with the full `reorg` from the saved old head; otherwise a
re-import that must intend exactly the saved transition), replays every
EXEC_READY observation without a decision natively and decides it as
`SIDE`, then switches to LIVE. `Begin` in LIVE refuses a block that is
already stored with its state.

## Limits

- Private local ETH slot only; every public cell stays NOT_RUN.
- The rejection after an intent is a native outcome fixture of the probe;
  the shipped binary has none.
- Hash state scheme only; the barrier keeps the state of every decided
  block on disk until E05-01.activation_gc.
- Without a mirror (until E05-01.registry), every `IMPORT` and `CANONICAL`
  decision keeps its obligation and marker, and `Open` and `Cleanup` visit
  every decision since the first one.
- Head changes without a new block (`SetCanonical`, `writeKnownBlock`,
  finality) do not pass the bridge yet (E01-02.lifecycle_seams).
- The clean-up of a mid-reorg completion is exercised only with an empty old
  branch above the fork (old head 299); the longer old branch is checked by
  source review.
