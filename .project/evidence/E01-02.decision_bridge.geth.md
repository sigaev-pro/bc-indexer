## What this block changes in Geth

Six patches of `adapters/geth/decision/native/patches.json`, applied after
the 23 admission patches, and the new file `core/extractor_decision.go`:

| Boundary | Change |
|---|---|
| `ProcessBlock` write section | After EXEC_READY, an observed write is one native decision; before the bridge opens (admission recovery) the block is not written |
| `writeBlockWithState` | StateDB commit, child-root barrier (`triedb.Commit(root)`, `SyncKeyValue`), `Intend`, then the block batch; a `SIDE` decision (`InsertBlockWithoutSetHead`) carries its marker there |
| `writeHeadBlock` | Only the head batch of the decided block carries the marker, then `SyncKeyValue`; the head batches that `reorg` writes for lower blocks carry none |
| `ProcessBlock` after the write | `Resolve`, then `Cleanup` |
| `eth/backend.go` | `AttachDecisions`: `OpenWithCleanup` with a `source_inputs.Purge` adapter, the recovery driver, `decision.Bridge.GoLive` |

The recovery driver settles an unresolved intent from native evidence (the
marker; a Geth bad block that is not stored; a block stored with its state,
completed with the full `reorg` from the saved old head; otherwise a
re-import that must intend exactly the saved transition), replays every
EXEC_READY observation without a decision natively and decides it as
`SIDE`, then switches to LIVE. `Begin` in LIVE refuses a block that is
already stored with its state.

## qa: AC-CAP-07 matrix (ETH, private local)

qa verdict for the private local ETH slot (chain ID 31337, Geth
`1df30b18`), from the retained records 03 at clean `ca88680`: run 03
(`run-record.json` SHA256 `9bf99858…7993`, result PASS) and its probe
observation (`probe/probe.json` SHA256 `3d2b294e…efba`, oracle failures:
none). Nothing was rerun for this verdict. AC-CAP-07-04 and 07-05 belong to
E05-01.registry and are not part of this block.

Oracle provenance: [ORACLE.md](../../test/harness/fixtures/admission_geth/ORACLE.md)
and the decision checks of `test/harness/fixtures/admission_geth/admission_geth.py`.
Every expected intent is computed there from the generated chain, the
formulas of the shared decision README (the independent
`test/harness/decision.py`) and the Geth evidence digest, never from the
probe output. The marker must equal `decision.marker_value` of that record
byte for byte.

How a loss is made (the probe, a test-only program on the product import
path `InsertChain`):

- An extractor-key crash (`before_sync/…`, `after_sync…`) is a SIGKILL of the
  attempt process at the named sync. The extractor records, capsule and log
  go through a power-loss store model that keeps writes in memory until
  `SyncKeyValue`, so every unsynced extractor write is lost.
- A native crash point (`native/…`) is a SIGKILL inside the patched
  `writeBlockWithState` or `reorg`. The probe first syncs the native writes
  made so far, so it models the power loss that keeps all of them.
- The native outcome fixture (`DecisionOptions.Outcome`) is a probe-only
  hook that refuses a named block after its intent. The shipped binary has
  none.

Every scenario also requires, for every decided block: the intent equal to
the independent record, the marker equal to its bytes, NATIVE_DECIDED with
`BATCH` for `IMPORT` and `CANONICAL` and `CHECKPOINT` for `SIDE`, no pin,
capsule, log or admission record left for a closed observation, and the
decision and admission counters of the oracle.

What each case rests on:

- AC-CAP-07-01 is checked at the EXEC_READY record. For Geth, every source
  input is in the capsule, which is sealed and synced before ADMITTED, and
  the execution log is empty (ORACLE.md, EXEC_READY check). So "raw corpus
  partly written" means here: the capsule and the closed empty log are
  durable and the EXEC_READY record is lost. That observation is not closed,
  and recovery must use the same ADMITTED obligation.
- AC-CAP-07-01, 07-02 and 07-03 rest on the probe: real SIGKILLs on the
  product import path, with the power-loss store model for extractor keys.
  The native unit tests (`decision_test.go`, preparation 03) only add to
  this.
- AC-CAP-07-03 at native crash points rests on the subset of native writes
  that keeps all of them (see above). A power loss that drops some unsynced
  native writes is not exercised.
- AC-CAP-07-06 rests on the probe's native outcome fixture, which the AC row
  allows. It is the only native refusal after an intent that the probe
  exercises; a native write failure after the intent leaves the intent
  unresolved until a restart (Geth decision README, "Limits"). The bad-block
  record the recovery reads is written by the
  shipped native code (`rawdb.WriteBadBlock`).

## Limits

- Private local ETH slot only; every public cell stays NOT_RUN.
- The rejection after an intent is a native outcome fixture of the probe;
  the shipped binary has none.
- Hash state scheme only; the barrier keeps the state of every decided
  block on disk until E05-01.activation_gc.
- Without a mirror (until E05-01.registry), every `IMPORT` and `CANONICAL`
  decision keeps its obligation and marker, and `Open` and `Cleanup` visit
  every decision since the first one.
- Head changes without a new block (`SetCanonical`, `writeKnownBlock`,
  finality) do not pass the bridge yet (E01-02.lifecycle_seams).
- The clean-up of a mid-reorg completion is exercised only with an empty old
  branch above the fork (old head 299); the longer old branch is checked by
  source review.
