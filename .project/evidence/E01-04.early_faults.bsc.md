## Run 01 results, private local BSC

Every case passes: 15 points × 2 variants. No probe step failed: no restart,
`GoLive` or import error, no undecided intent, and the re-import added
nothing. Each export holds both blocks; its native re-execution matched the
stored receipts, since the export stops the test otherwise. The native
result of the corpus blocks equals the smoke corpus in every case.

- **AC-SCP-03-01: PASS**, from both variants of the three H points.
  - `h.before-boundary-sync`: the gate opens in BOOTSTRAP, H is set at block
    1 after the restart, and only block 2 is exported.
  - The other two H points: the gate opens in RECOVERY, H is kept, and only
    block 2 is exported.
- **Opening mode.** Read from the `gate-opened` event of
  `bsclifecycle.Attach`: BOOTSTRAP in the 2 cases without a boundary and
  RECOVERY in the other 28.
- **Pending points.** A power loss dropped at least one write at each one,
  and the state after the restart is the state before the write.
- **Crash equals power loss at the pending points**, as on ETH. Pebble v1
  also keeps a small NoSync WAL record in process memory. The first recipe
  of block 0, a store close, would have flushed it. See correction 02.

## Technical decisions

- **Separate package.** The probe is a Go test in its own package,
  `extractor/bsc/faults` (`bscfaults_test`), next to the lifecycle package.
  The lifecycle probe's test package already defines many of the same names.
- **Copied code.** The fault store, its batch, the arming table, the
  catalog order and the state reading are the Geth probe's. A portable test
  compares every one of their declarations, methods included. `exportBlock`
  and its helpers are the BSC corpus probe's, also compared. The
  BSC-specific parts are tested for their stated differences:
  - `settleWAL` skips a WAL file that vanished between the listing and the
    stat;
  - `decisions` gives one row per member.
- **Decisions without members.** A decided intent without members, a
  FINALITY change of a BSC import, gives no decision row, as in
  `bsc_corpus.observation_of`.
- **Unchanged from the Geth block:** the H positions (block 1 for the H
  points, the genesis for the others), the panic as the fault, and the
  freezer on the OS file system.

## Limits

- Part B is open: the three BSC handoffs.
- At the pending points a crash reaches only the power-loss states.
- The model limits of block 0 apply.
- `unsynced_dropped` is the fault store's count of writes since the last
  completed sync, an upper bound.
- **The copy is not atomic.** The abandoned chain's goroutines still run
  while the probe copies its files one by one, and while the power-loss copy
  follows the reset of the live file system. A write in that window would
  enter the restarted store; no real crash or power loss produces that
  state. `copyFS` also skips a file that vanished since the listing. The run
  shows no such effect: every state after the restart is one the catalog
  allows.
- **Attempt result vs verdict.** `run.json` `result` records the attempt:
  PASS when the probe ran and the verdict is PASS or INCOMPLETE. qa reads
  the `verdict`. The Geth run record writes the verdict as its result.
