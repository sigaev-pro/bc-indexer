## Technical decisions

- **Separate package.** The probe is a Go test in its own package,
  `extractor/bsc/faults` (`bscfaults_test`), next to the lifecycle package.
  The lifecycle probe's test package already defines many of the same names.
- **Copied code.** The fault store, its batch, the arming table, the
  catalog order and the state reading are the Geth probe's. A portable test
  compares every one of their declarations, methods included. `exportBlock`
  and its helpers are the BSC corpus probe's, also compared. The
  BSC-specific parts are tested for their stated differences:
  - `settleWAL` skips a WAL file that vanished between the listing and the
    stat;
  - `decisions` gives one row per member.
- **Decisions without members.** A decided intent without members, a
  FINALITY change of a BSC import, gives no decision row, as in
  `bsc_corpus.observation_of`.
- **Unchanged from the Geth block:** the H positions (block 1 for the H
  points, the genesis for the others), the panic as the fault, and the
  freezer on the OS file system.

## Limits

- Part B is below ("Part B").
- At the pending points a crash reaches only the power-loss states.
- The model limits of block 0 apply.
- `unsynced_dropped` is the fault store's count of writes since the last
  completed sync, an upper bound.
- **The copy is not atomic.** The abandoned chain's goroutines still run
  while the probe copies its files one by one, and while the power-loss copy
  follows the reset of the live file system. A write in that window would
  enter the restarted store; no real crash or power loss produces that
  state. `copyFS` also skips a file that vanished since the listing. The run
  shows no such effect: every state after the restart is one the catalog
  allows.
- **Attempt result vs verdict.** `run.json` `result` records the attempt:
  PASS when the probe ran and the verdict is PASS or INCOMPLETE. qa reads
  the `verdict`. The Geth run record writes the verdict as its result.

### Technical decisions

- **Facts in the probe, verdicts in the judge.** The probe writes no
  expected value for the handoffs either; `handoff_verdicts` in
  `faults_bsc.py` applies the rules of the README. A malformed run, or one
  that misses a required fact, fails its handoff. A report that carries its
  own `handoffs` fails the result.
- **Reading of `bsc.pass-at-golive`** (block 0, correction 03). The catalog
  item says `GoLive` "is refused". `GoLive` runs under the guard, and the
  held import holds the guard on its own goroutine. So a concurrent held
  import is serialized: `GoLive` waits for it, then finds no pass open and
  sets H after it. `ErrOrder` applies only to a pass open in the same guard
  hold, which the lifecycle unit tests cover. The handoff passes when
  `GoLive` does not set H while the import is held (it waits, or returns
  `ErrOrder`), H is the held block, and that block is not captured. Geth and
  Bor read their `*.pass-at-golive` items the same way.
- **The action store.** A wrapper between the fault store and the database
  holds, fails or stops store calls. The catalog cases do not use it; the
  copied fault store stays equal to the Geth probe's.
- **The skip-block fault stops a goroutine.** BSC writes the head batch in a
  goroutine of `writeHeadBlock`; a panic there would end the test process.
  The fault syncs the store and stops that goroutine, so the head batch is
  never applied and the node is abandoned, as at a crash.
- **`recoverAndExport`.** The end of a catalog case (`GoLive`, import, final
  state, export, re-import) moved into a function that the handoffs reuse.
  The catalog cases run the same steps as in part A.
- **Deferred P3s of part A.** `faults_bsc.main` exit codes now have mutants
  (judge and refusal). `copyFS` is pinned through the Bor probe tests, which
  compare the Bor copy with this one (PR #178).

### Limits

- The head batch write error is not injected: native BSC ends the process
  on it (`log.Crit`), which is a process crash, covered by the catalog.
- `GoLive` with a held import is shown on the guard path. The `ErrOrder`
  refusal of the gate (a pass open in the same guard hold) stays covered by
  the lifecycle unit tests.
- The decision README lists a failed `Cleanup` among the error paths after
  the intent. It is not run: no mirror applies a decision until
  E05-01.registry.
- The "State after the restart" column of the store-error table is reported
  from run 02; the judge does not bind it. It binds the recovery outcome.
- The store errors are single errors at one place each; repeated or
  combined errors are not run.
- The skip-block case shows the outcome in which the block batch reached the
  disk. A power loss there drops the batch and gives the `intent-synced`
  state that the decision bridge probe covers.
