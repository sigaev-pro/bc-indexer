# E01-03.smoke_corpus: BSC (Parlia) block (#19)

This block generates the BSC corpus blocks with native BSC on the private
Parlia fixture and imports them through the accepted E01-02.decision_bridge
import path. It exports the native output (receipts, call-tracer frames, the
state before and after each user transaction, the Parlia system
transactions, the block-end state) and compares it with the independent
expected results of block 0 (`test/native_corpus/expected/bsc.json`, SHA-256
`939ee929b410ab0b637a2e8dc6fedff2db9ef53ebbfa0cc027de65cc02c3ba58`). Design,
commands and limits:
[test/native_corpus/bsc/README.md](../../test/native_corpus/bsc/README.md).

Scope: private local BSC only (chain 714, one validator, blocks 1 and 2
before Berlin and Plato). `bsc-mainnet` and `bsc-testnet` stay NOT_RUN (D96).
Under D101 the runs are short (the native part takes about 6 seconds). This
block changed no block 0 file and no shared `admission`, `decision` or
`source_inputs` file.

## Fixture inputs

ORACLE.md "Fixtures" names every input this block needs. The genesis is the
accepted private BSC genesis with the parent and the child added; the
sender is already there with the same 10 BNB, and the driver checks that. No
chain-config value is added. Block timestamps come from native Parlia
`Prepare` and the wall clock, so block hashes differ from run to run; they
bind the prepared input and are not expected values. The state roots of the
development run and run 01 are the same.

## Limits

The README "Limits" section explains each of them:
- private local BSC only, with the fee distribution before Kepler;
- the state around each user transaction comes from a native re-execution
  checked against the stored receipts; system transactions are not
  re-executed, and the block-end state binds their combined result;
- the mirror is the probe stand-in of the accepted BSC decision block;
- system-contract internals are not asserted (ORACLE.md).
