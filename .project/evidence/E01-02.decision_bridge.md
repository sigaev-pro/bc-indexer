# E01-02.decision_bridge: block 0, decision-core (partial, #17)

This block adds the client-independent core of E01-02.decision_bridge: the
transition intent, the native decision marker contract, the NATIVE_DECIDED
record with its single delivery obligation, the rejection of an intent, and
the decision checkpoint of a decision without public events. It also adds
the D100 items handed to this task: the admission step that closes EXEC_READY
observations (`Admission.Decide`), the deletion of the capsule, log and
admission records of closed observations (`source_inputs.Purge`,
`admission.OpenWithCleanup`), and one decision per block observed twice. The
shared `decision` package is copied byte for byte into
`adapters/{geth,bsc,bor}/decision`; the design is in its
[README](../../adapters/geth/decision/README.md).

Scope of this evidence: Go unit tests on an in-memory store model with
injected power loss, an end-to-end test with the real `source_inputs`,
admission and decision packages, portable identity and vector checks, and
single-check mutants. No native client runs here. The native marker patch,
the child-root barrier, the recovery driver and the per-client evidence are
later blocks (plan in PROJECT_STATUS), so every AC-CAP-07-01, 07-02, 07-03
and 07-06 profile cell stays NOT_RUN. This block gives no AC verdict and no
public-profile credit. #17 stays open.

## What the tests show

Expected digests and marker bytes come from `python3 test/harness/decision.py
vectors`, an independent Python implementation (`hashlib` and `json`) of the
README formulas, saved as `vectors.json`. The member EXEC_READY digest is the
independent admission vector, so the chain from the admission inputs to the
decision is checked end to end. `test_decision.py` (run by `bootstrap/ci`)
checks that the file matches the Python output, that the marker is the intent
JSON in field order, that every input changes the digests, and the module
layout.

The store model makes a write or delete durable only at a sync and, on power
loss, keeps a chosen subset of unsynced writes.

## Limits

- No native client, native marker patch, trie database or import path runs
  here; `Roots`, `Mirror` and the pin ledger are test fakes or store-backed
  models. The client blocks wire them (plan in PROJECT_STATUS).
- The mirror, READY and the applied-decision frontier are E05-01.registry;
  the decision to batch allocation is E02-01.semantic_descriptors. This
  block only defines the obligation they consume and the `Mirror` question
  the bridge asks.
- The bridge's `GoLive` requires every EXEC_READY observation to have a
  decision before LIVE, as the startup rule of NATIVE_CAPTURE_PROTOCOL
  says. The Bor admission recovery currently leaves a re-executed
  obligation EXEC_READY for a later live import; the Bor block completes its
  native import in RECOVERY_ONLY instead.
- Chunks that an interrupted `SealCapsule` or `Next` left without a durable
  record are not deleted by `Purge`; nothing reads them.
- Inputs of observations that an admission closed under plain `Open` and
  moved below its low-water mark are never purged; the client blocks switch
  to `OpenWithCleanup` before the first product run, and the private evidence
  stores from before the switch are discarded, not reused.
- Side blocks retained by `SIDE` decisions are released only by
  E05-01.activation_gc. Until then each keeps its parent pin live (the
  freezer limit, `PruneState`, `RequireRewindAllowed` and the BSC rewind by
  timestamp stay engaged), and the admission and decision low-water marks
  stop at the oldest retained block, so later records are not deleted and
  every `Open` reads them; capsules and logs are still purged at the close.
- `TestRejectedIntentKeepsRetainedSideBlocks` shows that a refused switch to
  a retained side block leaves it retained.
