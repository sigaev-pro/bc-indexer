# E01-02.inputs: Bor block (partial, #14)

The first Bor block (PR #140) wires the shared source-inputs core into the accepted Bor native
import path through a private local probe and runs the AC-CAP-04-01 to
AC-CAP-04-03 matrix (POLY only) on a private local fixture chain. The design
of the core is in the shared
[README](../../adapters/bor/source_inputs/README.md); this block does not
change `adapters/bor/source_inputs`.

Scope: private local evidence only, under the D96 and D98 boundary. Every
public profile cell (Polygon Mainnet, Amoy) stays NOT_RUN and gets no credit
from this block. The AC verdicts below are the owner verdicts of this task
for the private local profile only. The real EXEC_READY binding belongs to
E01-02.admission (D98 item 7). #14 stays open until the Geth and BSC blocks
and every remaining criterion pass.

## What the probe does

The probe source is `test/harness/fixtures/source_inputs_bor/`. Preparation
copies `main.go` to `cmd/extractor-bor-inputs-probe` inside the extracted Bor
source tree, the stub package `heimdallstub` next to it, and the shared
`inputs.go` and `inputs_test.go` to its `sourceinputs` subdirectory, then
builds offline with the accepted compiler.

- Bor runs its real consensus engine with the native HTTP
  `heimdall.HeimdallClient` (`HeimdallURL` set, no gRPC, no WebSocket). The
  client has no transport of its own, so it uses the process transport, which
  the probe replaces with the `heimdallstub` recorder. No network is used.
- The deterministic in-process Heimdall stub (D98 item 6) answers from fixed
  heimdall-v2 JSON files in `stub/`.
- Counted calls (D98): state sync event pages (`/clerk/time`) and spans by ID
  (`/bor/spans/<id>`). Each one goes through `Log.Next` of the shared package;
  the saved bytes are the raw response body at the transport boundary, before
  Bor decodes it. The request identity is `GET <path>?<query>` as Bor builds
  it. The latest-span and status calls are answered by the stub without the
  log; the record counts them.
- The store is a native pebble `ethdb.KeyValueStore`; a compile-time check
  asserts it satisfies `sourceinputs.Store`. In PR #140 the capsule items were
  the genesis file, the sealed `blocks.rlp` and the Bor source commit; the
  static manifest block below adds the remaining protocol items.
- A crash point is a real `SIGKILL` of the attempt process right after
  `Next` returned the durable response and before the transport hands it to
  Bor. The synced frontier is what survives a power loss, so the retry sees
  the same durable state as after a power loss at that point.
- After a completed import, `Finish` writes the final consumed manifest, and
  the probe writes and syncs a test-only stand-in marker
  `extractor-test-only-stand-in-exec-ready/<observation>` that holds its digest.

The qa oracle is
[ORACLE.md](../../test/harness/fixtures/source_inputs_bor/ORACLE.md) with
`expected.json`. The expected request sequence comes from the pinned Bor
source rules. The driver `test/harness/bor_source_inputs_probe.py` computes
the expected digests with the README formulas in
`test/harness/source_inputs.py` from the stub files and the capsule items. It
decodes the header times and state roots from `blocks.rlp` with its own RLP
reader; only the block hashes come from the generation record, which must
agree with the decoded headers.

## Static manifest block (Part of #14, 2026-11-10)

On 2026-11-10 the owner decided that the missing static manifest items are
finished inside #14. An audit found that no client capsule held every static
item that
[NATIVE_CAPTURE_PROTOCOL](../docs/NATIVE_CAPTURE_PROTOCOL.md) lists
("Admission и source pin"). This block completes the Bor capsule. Allowed
paths stay the Bor-only files; `adapters/*/source_inputs/` and
`test/harness/source_inputs.py` are unchanged (`source_inputs.py check`
exit 0).

One observation is the import of the sealed blocks 1 to 9 on top of the
genesis. Its capsule now holds these items, in this order:

| Item | Bytes | Protocol item |
|---|---|---|
| `genesis` | The genesis file | Chain config source |
| `blocks` | The sealed `blocks.rlp` | Header and body encodings |
| `parent-header` | RLP of the parent header (the genesis header) | Parent header |
| `parent-hash` | Keccak-256 of `parent-header` | Parent hash |
| `parent-root` | State root of `parent-header` | Parent root |
| `ancestor-headers` | RLP list of the headers Bor's snapshot walk may read, from the genesis or the nearest 1024-block checkpoint up to the parent (here only the genesis header) | Known ancestor headers |
| `chain-config` | The genesis `config` object with `bor.stateSyncConfirmationDelay` `{"0": 0}`, canonical JSON | Chain config, with the effective delay |
| `fork-id` | The EIP-2124 fork ID at block 9 (`core/forkid` `NewID`) | Fork digest |
| `native-commit` | The Bor source commit | Native commit |
| `normalization-profile` | `test-only-probe-v1`, as in the Geth block | Normalization profile |

Probe changes (`main.go`):

- The effective chain config is canonical JSON, and native Bor runs with
  exactly its decoding. Before this block, the in-memory delay was not in the
  capsule.
- Before the store opens, `checkItems` cross-checks the items: the parent
  header must hash to the parent hash of block 1, the parent hash and root must
  match it, the ancestor list must be linked, end at the parent and start at
  the genesis item's block or a checkpoint, the fork ID must equal native
  `NewID` over the chain config, and the profile must be the probe profile.
  A refused item is never sealed.
- After the backend starts, native Bor must run with the sealed config and
  with the parent as its genesis. The result field
  `native_config_matches_capsule` records the comparison.
- `-tamper ITEM` changes the last byte of one item (negative control).
  `-fault-state-sync-delay N` is the AC-CAP-04-02 fault: it changes the delay
  in memory after the seal.
- Generation also writes `parent-header.rlp`.

Why AC-CAP-04-02 changed: a changed chain config is now refused earlier, as a
capsule conflict, so the old fault (`-state-sync-delay 1` on retry) no longer
reaches the log. The new fault keeps the sealed capsule the same and makes
native Bor build a different request from the same sealed inputs. It is
test-only; the judge requires `native_config_matches_capsule` to be false only
in that attempt and true in every other logged attempt.

Independent expected values (qa, `bor_source_inputs_probe.py`): the driver
computes every item from the genesis file, the sealed blocks and the retained
`parent-header.rlp`, with its own Keccak-256 (tested against published
vectors, the 135/136/137-byte padding edges from `openssl dgst -keccak-256`
and a native Bor header hash) and its own RLP encoder. It accepts the parent
header only if its Keccak-256 is the parent hash of block 1, its number is 0,
and its time, gas limit and extra data equal the genesis file. It now also
checks every generated block hash and the chain links, which PR #140 took
from the generation record. Every logged attempt (completed, lost or refused
by the log) must report exactly the independent capsule items and digest.

Negative controls (scenario `control-capsule-items`, one store):

| Attempt | Change | Expected and observed |
|---|---|---|
| 0 | `parent-root` tampered, empty store | Refused: `capsule item parent-root disagrees with the parent header`; store stays empty |
| 1 | None | Fetches all five calls, imports the sealed head, binds the independent consumed digest |
| 2 | `parent-header` tampered | Refused: `... disagrees with the first sealed block` |
| 3 | `parent-hash` tampered | Refused: `... disagrees with the parent header` |
| 4 | `ancestor-headers` tampered | Refused: `... disagrees with the Bor snapshot walk` |
| 5 | `fork-id` tampered | Refused: `... disagrees with the chain config` |
| 6 | `normalization-profile` tampered | Refused: `... disagrees with the probe profile` |
| 7 | Chain config delay 1 | Refused: `conflicting input capsule` |
| 8 | None | Replays all five calls from the closed log, imports the sealed head, binds the same digest |

Every refused attempt exits 1 before any seal, counted call or import, and
leaves the store unchanged. The judge also requires the tampered set to be
exactly the six derived items; `chain-config` gets its control from the real
delay change (attempt 7) and from `control-delay`.

## Limits

- Private local fixture only: test genesis, one validator, stub Heimdall, no
  L1 and no real Heimdall. Native Bor consensus with public Heimdall data and
  every public cell stay with E05-01, E06 and E07 (D96, D98).
- The test genesis omits `stateSyncConfirmationDelay`, which Bor needs after
  Indore. Since the static manifest block, the effective config with the
  delay is the `chain-config` capsule item, and the AC-CAP-04-02 fault changes
  the delay in memory after the seal (test-only; see above). In PR #140 the
  capsule held only the unchanged genesis bytes.
- The latest-span and status calls are not logged. Their bytes do not enter
  execution directly, but the latest span ID bounds which span IDs Bor reads;
  a changed latest span could change the counted span requests, which the log
  refuses as a prefix conflict. In every completed attempt and every attempt
  refused by the log in runs 02 and 03, each was called once; the attempts
  refused before the seal in run 03 started no backend and made no call; the lost attempts record no uncounted calls.
- Process loss is a real SIGKILL after the frontier sync, not a power cut. It
  shows the retry path from the durable state; unsynced-write loss is covered
  by the shared unit tests on the power-loss store model.
