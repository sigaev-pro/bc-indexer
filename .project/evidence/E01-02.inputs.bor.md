## What the probe does

The probe source is `test/harness/fixtures/source_inputs_bor/`. Preparation
copies `main.go` to `cmd/extractor-bor-inputs-probe` inside the extracted Bor
source tree, the stub package `heimdallstub` next to it, and the shared
`inputs.go` and `inputs_test.go` to its `sourceinputs` subdirectory, then
builds offline with the accepted compiler.

- Bor runs its real consensus engine with the native HTTP
  `heimdall.HeimdallClient` (`HeimdallURL` set, no gRPC, no WebSocket). The
  client has no transport of its own, so it uses the process transport, which
  the probe replaces with the `heimdallstub` recorder. No network is used.
- The deterministic in-process Heimdall stub (D98 item 6) answers from fixed
  heimdall-v2 JSON files in `stub/`.
- Counted calls (D98): state sync event pages (`/clerk/time`) and spans by ID
  (`/bor/spans/<id>`). Each one goes through `Log.Next` of the shared package;
  the saved bytes are the raw response body at the transport boundary, before
  Bor decodes it. The request identity is `GET <path>?<query>` as Bor builds
  it. The latest-span and status calls are answered by the stub without the
  log; the record counts them.
- The store is a native pebble `ethdb.KeyValueStore`; a compile-time check
  asserts it satisfies `sourceinputs.Store`. The capsule items are the
  genesis file, the sealed `blocks.rlp` and the Bor source commit.
- A crash point is a real `SIGKILL` of the attempt process right after
  `Next` returned the durable response and before the transport hands it to
  Bor. The synced frontier is what survives a power loss, so the retry sees
  the same durable state as after a power loss at that point.
- After a completed import, `Finish` writes the final consumed manifest, and
  the probe writes and syncs a test-only stand-in marker
  `extractor-test-only-stand-in-exec-ready/<observation>` that holds its digest.

The qa oracle is
[ORACLE.md](../../test/harness/fixtures/source_inputs_bor/ORACLE.md) with
`expected.json`. The expected request sequence comes from the pinned Bor
source rules. The driver `test/harness/bor_source_inputs_probe.py` computes
the expected digests with the README formulas in
`test/harness/source_inputs.py` from the stub files and the capsule items. It
decodes the header times and state roots from `blocks.rlp` with its own RLP
reader; only the block hashes come from the generation record, which must
agree with the decoded headers.

## Limits

- Private local fixture only: test genesis, one validator, stub Heimdall, no
  L1 and no real Heimdall. Native Bor consensus with public Heimdall data and
  every public cell stay with E05-01, E06 and E07 (D96, D98).
- The test genesis omits `stateSyncConfirmationDelay`, which Bor needs after
  Indore; the probe sets it in memory (`{"0": 0}`; 1 for the AC-CAP-04-02
  fault). The capsule keeps the unchanged genesis bytes and does not hold the
  in-memory delay, which is why AC-CAP-04-02 reaches the log.
- The latest-span and status calls are not logged. Their bytes do not enter
  execution directly, but the latest span ID bounds which span IDs Bor reads;
  a changed latest span could change the counted span requests, which the log
  refuses as a prefix conflict. In every completed or refused attempt of run
  02, each was called once; the lost attempts record no uncounted calls.
- Process loss is a real SIGKILL after the frontier sync, not a power cut. It
  shows the retry path from the durable state; unsynced-write loss is covered
  by the shared unit tests on the power-loss store model.
