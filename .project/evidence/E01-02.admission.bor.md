## Limits

- Private local fixture only: test genesis, one validator, stub Heimdall, no
  L1 and no real Heimdall. Public cells stay with E06 and E07 (D96, D98, D99).
- Process loss is a real SIGKILL right after a sync. A process kill keeps
  unsynced writes, so loss of unsynced writes (for example an ADMITTED record
  written but not synced) is covered only by the unit tests of the shared core.
- The probe shows the `SetHead` and startup prune-recovery refusals inside the
  probe process, which installs the hooks the same way as the shipped `bor`;
  the shipped binary itself runs `snapshot prune-state`. The freezer limit is
  covered by the rawdb and borimport tests, not by a native freeze (the
  fixture chain is far below the 90000-block immutability threshold).
- See the native README for the remaining limits: other Heimdall readers
  during a window (RPC), `bor snapshot prune-block`, the lock order
  constraint, the caller of `Start` and the `bor server` profile check
  (E01-02.lifecycle_seams), the capture producer on the chain
  (E04-04.import_pressure), and duplicate observations of one block after a
  recovery (E01-02.decision_bridge decides once per candidate).
