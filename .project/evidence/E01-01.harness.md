# E01-01.harness: local Ethereum import slice

This is a partial implementation for issue 12, based on accepted main
`0388a975e008a1f6d8335c29687c086d8c975020`. Issue 12 remains open. No public
profile, full quick suite, capture, consensus, NATS delivery, lifecycle AC, or
stage gate is accepted by this slice.

The public CLI admits raw-byte-bound accepted build and fixture inputs, initializes
fresh local state, imports one value-transfer block and one empty block, compares
both native account states with independently worked expectations, and checks
the full native export. The local chain identity is distinct from its public
Ethereum build association. See [the runner contract](../../test/harness/README.md)
and [the oracle](../../test/harness/fixtures/ORACLE.md).

The accepted actual BuildManifest SHA256 is
`cb42ed6d004f1fe71d3d40f95a6a47a11aeb35fcb0211b553f42a62f4e1d1c39`.
The accepted Geth binary SHA256 is
`3aec32655459fba4dd7db68dfc19e463003b954b359bb3377d75c744280726fe`,
source commit `1df30b18d9ed35ee9d28ffd4648442c2204554ad`. The runner uses the
accepted pinned Debian image with no network or new image acquisition.

## Retained development evidence

The first red admission test rejected the absent implementation, then passed when
changed binary bytes were rejected before output/native dispatch. Independent
oracle comparison and owned timeout behavior each followed a failing behavioral
test. Additional controls cover raw genesis/RLP/oracle/manifest changes, closed
fields/types, private identity, omitted blocks/accounts, symlinks, full-chain
prefixes, parent loss, signals, and uncertain-cleanup dispatch fencing.

Preparation attempt 1 failed because `go run` tried to execute its output from
the container's non-executable `/tmp`. Native module verification had passed;
native import had not run. Its proof SHA256 is
`c5cbfcb08b9f57647579ea8a751e8184328bffc2d78f502082c170998795fd34`,
measured preparation 120.928356807 seconds, owner nonce
`0a299851234b42c8817ae788847df792`. Both command cleanup records passed.

The correction built the generator into its owned output directory and then
executed it in a separate bounded command. It preserved non-executable `/tmp`.
Attempt 2 linked the failed attempt and correction, with proof SHA256
`02929a32b5bdf8fd113d67f033f7c50b18cf98f48b9f8f402eff98e2b5f34829`,
measured preparation 71.894041667 seconds, owner nonce
`5ee959bbd694469d89e0780427756ddb`. All three commands passed with cleanup.
The generator did not read or write the expected-results file.

The initial native import proof SHA256
`8602c12fa3b43d8e464b75a5b48d46b461b9989e54a731f98d3aa651ef71954f`
recorded a local PASS in 5.988843783 measured seconds, owner nonce
`0cb1e688e4d14895bd36fbf810396e89`. Both account states and full raw export matched.
Subsequent development controls also detected native corrupt RLP, a wrong oracle,
and admission tampering. These are development diagnostics, not final-candidate
acceptance: the ownership guard changed afterward.

Root found that polling/reaping an exited leader could leave its descendant alive.
A direct subprocess regression reproduced that live descendant. The repair uses
`waitid(WNOWAIT)` to retain ownership through group termination, then checks group
and container absence separately. The regression and 11 other portable tests
passed, with no remaining owned fixture processes. Earlier failures remain
retained; none was relabeled as success.
