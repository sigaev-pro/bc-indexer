## Fixture input not named in ORACLE.md

ORACLE.md "Fixtures" says the Bor fixture is the test genesis with only the
corpus accounts added. This block also sets `bor.stateSyncConfirmationDelay`
`{"0": 0}` in the chain config:
- **Why it is needed:** without the value native Bor panics at the first
  state sync after Indore (block 3 in the test genesis). There
  `CalculateStateSyncDelay` reads an empty map (`params/config.go`,
  `borKeyValueConfigHelper`).
- **Precedent:** the accepted admission fixture uses the same value
  (`test/harness/fixtures/admission_bor/expected.json`).
- **Effect:** with delay 0 the state sync query of block 4 ends at its time,
  nine seconds after the genesis. The stub's event, recorded one second after
  the genesis, therefore lands at block 4 as the oracle states. Any delay of
  at most seven seconds gives the same result.
- **Oracle:** no expected value changes for any delay of at most seven
  seconds; a longer delay would move the event past block 4 and fail the
  system-action case. The oracle was not changed.

Both reviewers accepted the value; ORACLE.md may name it in a later block 0
change.
