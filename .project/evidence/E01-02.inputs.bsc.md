# E01-02.inputs: BSC block (partial, #14)

This block wires the shared source inputs core
([README](../../adapters/bsc/source_inputs/README.md)) into the accepted BSC
native import path through a private local probe. It shows four things on
the accepted private BSC Parlia fixture:

1. The static input capsule holds every static manifest item that
   NATIVE_CAPTURE_PROTOCOL lists for BSC, and it is persisted and synced
   before execution.
2. Each consumed native dependency response is persisted before Parlia
   consumes it.
3. Replay hands Parlia the saved bytes.
4. Block 2 replays alone on a home that never imported block 1. Its headers
   come from the capsule; its parent body and state come from the parent
   pin, and a missing parent state stops the replay before execution.

Scope: private local evidence under the D96 and D98 boundaries. AC-CAP-04-01
to AC-CAP-04-03 apply to POLY only, so this block issues no AC verdict
(`ac_verdict: null`) and earns no public-profile credit
(`public_profile_credit: false`). Every public profile cell stays NOT_RUN.
#14 stays open.

## Design

Files:

- `test/harness/fixtures/source_inputs_bsc/bsc_inputs.go`: the wiring.
- `test/harness/fixtures/source_inputs_bsc/bsc_inputs_test.go`: unit tests and
  the native probe.
- `test/harness/bsc_source_inputs.py`: the driver (`prepare`, `run`,
  `mutants`).
- `test/harness/fixtures/source_inputs_bsc/test_bsc_source_inputs.py`: portable
  controls of the driver's checks (run by `bootstrap/ci`).
- `source_inputs_bsc.mutants.json` and `bsc_driver.mutants.json`: the mutant
  tables.

`prepare` installs `inputs.go`, `inputs_test.go` and the two probe files into
`extractor/source_inputs` of the extracted BSC source tree. It refuses an
existing directory. It then runs `gofmt -l`, `go vet` and `go test -c` with
the accepted offline compiler and module cache.

**Dependency boundary.** In the pinned BSC source
(`consensus/parlia/parlia.go` and `snapshot.go`), the Parlia engine uses the
database handle it receives only in `loadSnapshot` (`Get` of `parlia-` plus
the block hash) and `Snapshot.store` (`Put`). `ParliaDB` wraps that handle.
Only the engine receives it; the BlockChain keeps the native database. So
only reads through Parlia's own handle are logged dependency responses. Header
reads through `ChainHeaderReader` (for block 2, `chain.GetHeader` of block 1
in `snapshot()`) are known before execution, so their headers are static
capsule items (see Static manifest). The parent body and the parent state are
native-owned data under the parent pin of E01-02.pins, not static inputs.

- Every `Get` and `Has` goes through `Log.Next` of the current observation.
- Inside an observation, a read must use a key that the sealed capsule
  declares in `parlia-snapshot-keys`. A read before `Declare`, or of any
  other key, stops the wrapper (`ErrUndeclaredRead`).
  The request is the tag `bsc-parlia-db-get-v1` (or `bsc-parlia-db-has-v1`),
  one zero byte and the exact key.
- The response is one status byte (`0x00` missing, `0x01` present). For
  `Get`, the exact value follows the status byte.
- Writes and every other method pass through unchanged.

**Fail closed.** Each of these stops the wrapper for good:

- a read outside an observation;
- `NewIterator`, which has no logged form;
- a native read error;
- any log error;
- a malformed saved response.

Parlia turns a failed snapshot read into a regenerated snapshot, so it hides
these errors. The probe therefore checks `Detach()` after every import, and
`Finish` refuses a stopped log.

**Observation.** `observe` runs these steps in order:

1. Seal the capsule (`SealCapsule` syncs it).
2. Read the sealed capsule back with `ReadStatic`, which checks its items
   against each other, and declare its snapshot keys.
3. Open the log.
4. Emit `execute`.
5. Open the native chain with a fresh Parlia engine (hash scheme, full GC,
   native snapshots off).
6. Import one block.
7. Stop the chain and check `Detach()`.
8. Run `Finish`.

The engine's startup reads happen inside the observation.

**Static manifest.** NATIVE_CAPTURE_PROTOCOL lists the static manifest items:
the header, body and encodings; the parent root and hash; the chain config
and fork digest; the native commit and normalization profile; and the known
ancestor headers and BSC snapshot dependencies. The capsule items, in order,
are:

| Item | Content | Protocol item |
|---|---|---|
| `block-rlp` | Exact fixture encoding of the block (header and body); it re-encodes to the same bytes | header, body, encodings |
| `parent-hash` | Hash of the parent header | parent hash |
| `parent-header-rlp` | RLP of the parent header | parent header |
| `parent-root` | State root of the parent header | parent root |
| `ancestor-headers-rlp` | RLP list of the headers from the grandparent down to the ancestor floor, newest first | known ancestor headers |
| `genesis-json` | Exact genesis file, which holds the chain config | chain config |
| `fork-id` | EIP-2124 fork identifier of the block's number and time, `{"hash","next"}` JSON as in the Geth block | fork digest |
| `parlia-snapshot-keys` | `{"checkpoint","keys"}` JSON: the checkpoint at or below the parent and the key `parlia-` plus its hash | BSC snapshot dependencies |
| `native-commit` | BSC source commit from the BuildManifest | native commit |
| `normalization-profile` | `test-only-probe-v1`, the same test-only value as the Geth block | normalization profile |
| `state-profile` | `state.scheme=hash;gcmode=full;snapshots=off` | capture profile |

The ancestor floor of block `n` (`AncestorFloor`) is the lower of two
numbers, both read from the pinned source: the Parlia checkpoint below the
parent, `(n-1)/1024*1024`, where the snapshot walk stops, and `n-256`, the
oldest block that BLOCKHASH can read. For block 1 the window is empty (its
parent is the genesis). For block 2 it holds the genesis header. The window
does not cover two other Parlia header reads; see Limitations.

Only the snapshot *key* is static. The snapshot content is a native database
read, so it stays a logged dependency response. `DecodeStatic` refuses a
capsule whose parent header does not hash to `parent-hash`, whose
`parent-root` differs from the parent header, whose ancestors do not link by
hash and number or do not fill the window, whose snapshot keys differ from
the headers, or whose block is not the parent's child.

**Single-block replay.** `SeedParent` prepares a home that holds only the
genesis for a native-only replay of block `n` without importing its
predecessors:

- The parent and ancestor headers come from the capsule. They get canonical
  marks and total difficulty. The total difficulty starts from the home's
  value below the lowest capsule header (here the genesis, written from
  `genesis-json`).
- The parent body and the parent state come from the pinned home. The native
  BlockChain needs both: `ValidateBody` calls `HasBlockAndState` on the
  parent, and execution reads the parent state. The body must match the
  capsule's parent header (transaction root, uncle hash, withdrawals). Each
  state node and code must match its hash.
- `CheckParentState` then walks every account trie node, storage trie node
  and code under `parent-root` in the replay home. If any is missing, the
  replay stops before execution with `ErrParentState`.

**Trace.** The store wrapper `TracedStore` records each core write by record
kind and each sync. The wrapper records each native `fetch` and each
`handoff`, with the request and response bytes. The probe records `execute`,
`finished`, `crash`, `seed` and `preflight`.

**Probe steps (`TestNativeBSCInputs`).**

1. *Capture child.* The test binary re-runs itself as
   `TestNativeBSCInputsChild` on home `capture`. Block 1 completes. At the first
   hand-off of block 2, the child kills itself with SIGKILL. That point is
   after the response is durable and before Parlia receives it.
2. *After the crash.* The parent reopens `capture` and reads both capsules,
   both durable frontiers, and the saved block 2 response. The response is
   read by a replaying `Next` whose fetch fails if it is called. It must equal
   `0x01` plus the stored snapshot.
3. *Resume.* Block 2 runs again on `capture`. The saved prefix replays without
   a native read. A read beyond the frontier is a new logged response.
4. *Control.* On home `control`, the probe imports block 1 live. It then
   tampers the stored genesis snapshot: every validator address gets its first
   byte flipped. Block 2, imported live with a fresh engine, must fail with
   `unauthorized validator`.
5. *Native-only replay.* On a fresh home `replay`, both blocks run in order.
   The static inputs come from the fixture files, and re-sealing checks that
   they equal the capsule stored in `capture`. The dependency responses come
   from the saved, closed logs of `capture`. Between the blocks, the probe
   tampers the replay home's stored snapshot the same way. Block 2 must still
   import. Each hand-off must return the saved bytes, never the tampered ones,
   with no native read and no write.
6. *Single-block replay.* On fresh home `single`, which gets only the genesis,
   `SeedParent` installs the block 2 capsule's headers and copies the parent
   body and state from `capture` (standing in for the parent pin). After
   `CheckParentState`, block 2 runs alone with the saved log of `capture`.
   Block 1 is never imported there. Two controls follow:
   - `single-no-state` seeds everything except the parent state. The preflight
     must refuse with `parent state is missing from the home`, and block 2
     must never execute.
   - `single-no-headers` seeds the body and state but not the capsule headers.
     A live import of block 2 must fail with `unknown ancestor`.

**Driver checks (`evaluate`).** The driver does not trust the probe's own
assertions. From the fixture inputs and the README formulas (through
`source_inputs.py`), it recomputes:

- every capsule digest and item list, and the exact bytes of every static
  item. A pure-Python Keccak-256 checks that the genesis header from the
  report hashes to the ProfileManifest genesis, that each fixture header
  hashes to its fixture hash and links to its parent, and the snapshot key.
  The fork id is recomputed from `genesis.json` with the EIP-2124 rules. The
  Keccak and fork-id code has published test vectors in the portable tests;
- the consumed-manifest digest of both blocks, from the handed request and
  response bytes.

From the traces, it checks:

- Every capsule write is followed by a sync before `execute`, and no read
  precedes `execute`.
- Each new hand-off follows exactly `fetch`, one or more `put:entry-chunk`,
  `put:entry`, `sync`, `put:frontier`, `sync`. A replayed hand-off has no
  event since the previous anchor.
- The close is `put:closed`, `sync`, or nothing for an already closed log.
- The capture trace ends with the crash right after the first, new hand-off
  of block 2, and that read is a Parlia snapshot `Get` with a present value.
- In the resume, the first hand-off replays the crashed request and response,
  and the fetch count equals the number of new hand-offs.
- In the control, the snapshot digests before and after the tamper equal the
  replay home's.
- The replay trace has no fetch and no write, and no replay hand-off returns
  the tampered response.
- Heads and state roots equal the fixture's prepared blocks.
- Every logged read in every trace uses a key that its capsule declares.
- The single-block replay trace starts with a successful seed (one header,
  state nodes, a body digest) and preflight, has no fetch, no write and no
  block 1 event, replays every response, and ends with the resumed block 2
  manifest.
- In `single-no-state`, the seed copies no state node, the preflight reports
  the missing parent state, and nothing executes. In `single-no-headers`, the
  seed writes no header but the same state, the preflight passes, the import
  fails with `unknown ancestor` at head 0, and nothing executes.

## Limitations

- The fixture has two blocks and no epoch or checkpoint boundary beyond
  genesis. So the only consumed dependency is the genesis Parlia snapshot:
  missing for block 1 and present for block 2. Parlia's `ethAPI` is nil in
  this import path, as in the accepted fixture import, so no system-contract
  call is a dependency here.
- **Parent state.** A native-only replay still needs the parent state, and
  the native BlockChain also needs the parent body. Both are native-owned data
  under the parent pin (E01-02.pins), not static inputs. The probe copies them
  from the pinned `capture` home with hash checks. `CheckParentState` must
  pass before execution, so a replay home without the complete parent state
  fails closed (control `single-no-state`). Copying state between homes is a
  probe stand-in. In the product, the replay runs on the native home that
  holds the pin.
- **Ancestor window.** The window rule is derived from the pinned Parlia
  `snapshot()` walk and the BLOCKHASH range. A snapshot-walk read below the
  floor finds no header in a seeded home and fails the import. The rule does
  not cover two other Parlia header reads in the pinned source:
  - the validator-switch lookback: at block `number % epoch ==
    minerHistoryCheckLen()`, `snap.apply` calls `FindAncientHeader`
    (`consensus/parlia/snapshot.go:384`), which reads back to the epoch
    block through `chain.GetHeader`. That block can lie below the floor. A
    missing header fails the import with `ErrUnknownAncestor`, so this read
    fails closed, but the capsule does not hold its header;
  - the finalized header: `GetFinalizedHeader`
    (`consensus/parlia/parlia.go:2286`) reads the header named by the
    snapshot attestation. A missing header is not an error:
    `GetFinalizedNumber` (`core/blockchain.go:792`) returns 0. So this read
    does **not** fail closed; it changes the finality result.
  On this fixture the window holds only the genesis, so a window of more than
  one header, a checkpoint above genesis, BLOCKHASH reads and both reads above
  are not exercised natively. The unit tests cover the window rule, a
  three-header window, and the 255-header window of block 1025.
- **Total difficulty.** The seed takes the total difficulty below the lowest
  capsule header from the replay home (here the genesis). For a longer chain,
  that value is native chain data of the pinned home.
- **Snapshot keys.** The declared key covers a fresh engine, which has no
  in-memory snapshots. A long-running engine may read fewer keys, never
  others.
- The fork id and the ancestor window are recomputed by the driver from the
  fixture. The genesis header comes from the probe report and is checked only
  by its hash.
- In the replay steps, the block and genesis that native code receives come
  from the fixture files; re-sealing checks that they equal the stored
  capsule. In the single-block replay, the headers come from the stored
  capsule of `capture`.
- `ParliaDB` logs concurrent reads in the order they take its lock. On this
  fixture, all reads use one key, so their order cannot differ. Concurrent
  reads of different keys (for example, across an epoch or checkpoint
  boundary) are not exercised. A different order on replay would fail closed
  with `ErrPrefixConflict`. This is left to E01-02.admission.
- The crash test is a process crash (SIGKILL) on the native pebble store.
  Power-loss cases are covered by the core's unit tests on a store model, not
  natively.
- Wiring into the product import path, the real EXEC_READY binding and the
  native retention patches belong to E01-02.admission (D98). Public profiles
  belong to E06 and E07.

## Still missing against the protocol's static list for BSC

Every static manifest item of NATIVE_CAPTURE_PROTOCOL now has a capsule item
(see Static manifest). These limits are handed on:

- **Product import path (E01-02.admission).** The capsule is sealed by the
  private probe for one block per observation. Building it inside the real
  import, binding the consumed digest to the real EXEC_READY, and replaying on
  the native home that holds the parent pin belong to E01-02.admission (D98).
  The probe copies the parent body and state from the pinned home instead.
- **Parent body, parent state and total difficulty.** They are native-owned
  data under the parent pin (E01-02.pins), not static items. The native
  BlockChain needs the parent body (`HasBlockAndState`) and the total
  difficulty below the capsule headers. A missing parent state fails closed
  before execution (`CheckParentState`). The pin patches that keep them belong
  to E01-02.admission (D98).
- **Ancestor window.** On this two-block fixture the window holds only the
  genesis. A window above a checkpoint, a stored checkpoint snapshot above
  genesis, BLOCKHASH reads and the Parlia trusted-checkpoint path (more than
  90,000 piled-up headers, `number % 1000 == 200`) are not exercised
  natively. Public profiles (E06, E07) and E01-02.admission must cover them.
- **Ancestor headers outside the window.** The validator-switch lookback
  (`FindAncientHeader`) and the finalized header (`GetFinalizedHeader`) can
  read headers below the window (see Limitations). The first fails closed on
  a missing header; the second silently returns finality 0. Extending the
  window, or making the finalized read fail closed, belongs to
  E01-02.admission; E06 and E07 must exercise both on public profiles.
- **Parent-state check cost.** `CheckParentState` walks every node and code
  of the parent state. That is fine on the fixture (129 nodes, 11 codes) but
  is not a workable per-block check on mainnet. The product needs a different
  completeness check (E01-02.admission).
- **Snapshot dependencies.** Only the snapshot key is static; the content
  stays a logged dependency response. The declaration assumes a fresh engine.
  Parlia system-contract calls (`ethAPI`, nil in this import path) are not
  covered; they belong to E01-02.admission and E06/E07.
- **Fork digest.** The EIP-2124 fork id covers every BSC fork that the pinned
  `ChainConfig` holds as a `...Block` or `...Time` field. The Parlia
  parameters (`epoch`, `period`) are in `genesis-json`, not in the fork id.
  The driver recomputes the fork id from JSON keys that end in `Block` or
  `Time`; this matches the Go field names for this genesis only. Go's
  `DecodeStatic` checks only that `fork-id`, `genesis-json`, `native-commit`,
  `normalization-profile` and `state-profile` are present; the driver's
  recompute and the re-seal equality check their values.
- **Normalization profile.** `test-only-probe-v1` is a test-only name; the
  product profile belongs to E04 normalization.
- **Concurrent reads.** The read order of concurrent Parlia reads of
  different keys is not exercised (see Limitations).
