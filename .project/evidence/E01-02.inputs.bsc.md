# E01-02.inputs: BSC block (partial, #14)

This block wires the shared source inputs core
([README](../../adapters/bsc/source_inputs/README.md)) into the accepted BSC
native import path through a private local probe. It shows three things on
the accepted private BSC Parlia fixture:

1. The static input capsule is persisted and synced before execution.
2. Each consumed native dependency response is persisted before Parlia
   consumes it.
3. Replay hands Parlia the saved bytes.

Scope: private local evidence under the D96 and D98 boundaries. AC-CAP-04-01
to AC-CAP-04-03 apply to POLY only, so this block issues no AC verdict
(`ac_verdict: null`) and earns no public-profile credit

## Design

Files:

- `test/harness/fixtures/source_inputs_bsc/bsc_inputs.go`: the wiring.
- `test/harness/fixtures/source_inputs_bsc/bsc_inputs_test.go`: unit tests and
  the native probe.
- `test/harness/bsc_source_inputs.py`: the driver (`prepare`, `run`,
  `mutants`).
- `test/harness/fixtures/source_inputs_bsc/test_bsc_source_inputs.py`: portable
  controls of the driver's checks (run by `bootstrap/ci`).
- `source_inputs_bsc.mutants.json` and `bsc_driver.mutants.json`: the mutant
  tables.

`prepare` installs `inputs.go`, `inputs_test.go` and the two probe files into
`extractor/source_inputs` of the extracted BSC source tree. It refuses an
existing directory. It then runs `gofmt -l`, `go vet` and `go test -c` with
the accepted offline compiler and module cache.

**Dependency boundary.** In the pinned BSC source
(`consensus/parlia/parlia.go` and `snapshot.go`), the Parlia engine uses the
database handle it receives only in `loadSnapshot` (`Get` of `parlia-` plus
the block hash) and `Snapshot.store` (`Put`). `ParliaDB` wraps that handle.
Only the engine receives it; the BlockChain keeps the native database. So
only reads through Parlia's own handle are logged dependency responses. Header
reads through `ChainHeaderReader` (for block 2, `chain.GetHeader` of block 1
in `snapshot()`) and the parent state come from the home's native database
without logging; they are native-owned state under E01-02.pins. See
Limitations.

- Every `Get` and `Has` goes through `Log.Next` of the current observation.
  The request is the tag `bsc-parlia-db-get-v1` (or `bsc-parlia-db-has-v1`),
  one zero byte and the exact key.
- The response is one status byte (`0x00` missing, `0x01` present). For
  `Get`, the exact value follows the status byte.
- Writes and every other method pass through unchanged.

**Fail closed.** Each of these stops the wrapper for good:

- a read outside an observation;
- `NewIterator`, which has no logged form;
- a native read error;
- any log error;
- a malformed saved response.

Parlia turns a failed snapshot read into a regenerated snapshot, so it hides
these errors. The probe therefore checks `Detach()` after every import, and
`Finish` refuses a stopped log.

**Observation.** `observe` runs these steps in order:

1. Seal the capsule (`SealCapsule` syncs it).
2. Open the log.
3. Emit `execute`.
4. Open the native chain with a fresh Parlia engine (hash scheme, full GC,
   native snapshots off).
5. Import one block.
6. Stop the chain and check `Detach()`.
7. Run `Finish`.

The engine's startup reads happen inside the observation. The capsule items,
in order, are:

- `block-rlp`: the exact fixture encoding; the test checks that it
  re-encodes to the same bytes.
- `parent-hash`.
- `genesis-json`.
- `native-commit`: the BSC source commit from the BuildManifest.
- `state-profile`: `state.scheme=hash;gcmode=full;snapshots=off`.

**Trace.** The store wrapper `TracedStore` records each core write by record
kind and each sync. The wrapper records each native `fetch` and each
`handoff`, with the request and response bytes. The probe records `execute`,
`finished` and `crash`.

**Probe steps (`TestNativeBSCInputs`).**

1. *Capture child.* The test binary re-runs itself as
   `TestNativeBSCInputsChild` on home `capture`. Block 1 completes. At the first
   hand-off of block 2, the child kills itself with SIGKILL. That point is
   after the response is durable and before Parlia receives it.
2. *After the crash.* The parent reopens `capture` and reads both capsules,
   both durable frontiers, and the saved block 2 response. The response is
   read by a replaying `Next` whose fetch fails if it is called. It must equal
   `0x01` plus the stored snapshot.
3. *Resume.* Block 2 runs again on `capture`. The saved prefix replays without
   a native read. A read beyond the frontier is a new logged response.
4. *Control.* On home `control`, the probe imports block 1 live. It then
   tampers the stored genesis snapshot: every validator address gets its first
   byte flipped. Block 2, imported live with a fresh engine, must fail with
   `unauthorized validator`.
5. *Native-only replay.* On a fresh home `replay`, both blocks run in order.
   The static inputs come from the fixture files, and re-sealing checks that
   they equal the capsule stored in `capture`. The dependency responses come
   from the saved, closed logs of `capture`. Between the blocks, the probe
   tampers the replay home's stored snapshot the same way. Block 2 must still
   import. Each hand-off must return the saved bytes, never the tampered ones,
   with no native read and no write.

**Driver checks (`evaluate`).** The driver does not trust the probe's own
assertions. From the fixture inputs and the README formulas (through
`source_inputs.py`), it recomputes:

- every capsule digest and item list;
- the consumed-manifest digest of both blocks, from the handed request and
  response bytes.

From the traces, it checks:

- Every capsule write is followed by a sync before `execute`, and no read
  precedes `execute`.
- Each new hand-off follows exactly `fetch`, one or more `put:entry-chunk`,
  `put:entry`, `sync`, `put:frontier`, `sync`. A replayed hand-off has no
  event since the previous anchor.
- The close is `put:closed`, `sync`, or nothing for an already closed log.
- The capture trace ends with the crash right after the first, new hand-off
  of block 2, and that read is a Parlia snapshot `Get` with a present value.
- In the resume, the first hand-off replays the crashed request and response,
  and the fetch count equals the number of new hand-offs.
- In the control, the snapshot digests before and after the tamper equal the
  replay home's.
- The replay trace has no fetch and no write, and no replay hand-off returns
  the tampered response.
- Heads and state roots equal the fixture's prepared blocks.

## Limitations

- The fixture has two blocks and no epoch or checkpoint boundary beyond
  genesis. So the only consumed dependency is the genesis Parlia snapshot:
  missing for block 1 and present for block 2. Parlia's `ethAPI` is nil in
  this import path, as in the accepted fixture import, so no system-contract
  call is a dependency here.
- Only reads through the database handle that Parlia receives are logged.
  Header reads through `ChainHeaderReader` and the parent state come from the
  home's native database without logging. The capsule holds `parent-hash` but
  not the parent header, the parent state root or ancestor headers, which
  NATIVE_CAPTURE_PROTOCOL lists among the static items. Those BSC capsule
  items remain open work of #14 (E01-02.inputs); only the binding of the
  capsule to the real import belongs to E01-02.admission (D98). Until they
  are added, a native-only replay of block N needs its predecessors imported
  into the same home first, as the probe does.
- In the replay, the block and genesis that native code receives come from
  the fixture files; re-sealing checks that they equal the stored capsule.
  Only the dependency responses are served from the saved log.
- `ParliaDB` logs concurrent reads in the order they take its lock. On this
  fixture, all reads use one key, so their order cannot differ. Concurrent
  reads of different keys (for example, across an epoch or checkpoint
  boundary) are not exercised. A different order on replay would fail closed
  with `ErrPrefixConflict`. This is left to E01-02.admission.
- The crash test is a process crash (SIGKILL) on the native pebble store.
  Power-loss cases are covered by the core's unit tests on a store model, not
  natively.
- Wiring into the product import path, the real EXEC_READY binding and the
  native retention patches belong to E01-02.admission (D98). Public profiles
  belong to E06 and E07.
