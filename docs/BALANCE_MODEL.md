# Действия и изменения нативных балансов

Статус: контракт сбора и нормализации до NATS.IO, D07/D10/D16/D17. Все транзакции и их эффекты обязательны. Изменения вне транзакций — optional, разрешено не реализовывать при усложнении кода. Детальная модель действий ещё не завершена.

Собираются транзакции, вызовы, причинно связанные действия и адресные эффекты. Самостоятельные системные операции — только при включённом optional расширении. Приход и расход по 10 в одной успешной транзакции — два действия даже при нулевом итоговом diff. Итоговые before/after и действия — разные согласованные представления; их нельзя суммировать как независимые изменения.

При старте собирается выбранная история (default 3 часа), затем live. Полный начальный snapshot адресов не требуется. Отсутствие наблюдения не означает нулевой баланс. YAML управляет поддержанным профилем сети и параметрами сбора.

## Сложные случаи и необходимые данные

| Случай | Почему простого списка tx.value недостаточно | Что сохранять и проверять |
|---|---|---|
| Дочерний вызов успешен, родитель позже делает revert | Локальный успех не означает сохранённый перевод | Исходный outcome, причинная связь и итоговая применимость эффекта |
| Внешняя транзакция неуспешна | Изменения вызова отменены, часть транзакционных эффектов сохраняется | Fee effects отдельно от отменённых value effects; сверка с native state |
| DELEGATECALL/CALLCODE, self-transfer | Значение в контексте вызова не доказывает отдельный перевод | Нативные адреса контекста и реальные balance effects; нельзя суммировать все frame.value |
| Gas purchase и возврат неиспользованного газа | Низкоуровневые записи и итоговая комиссия — разные представления одного процесса | Родные причины, порядок и финальная комиссия без двойного учёта |
| Withdrawals, награды, burn/mint и системные действия | У эффекта может не быть tx hash, пары sender/receiver или сохранения общей суммы адресных балансов | Native operation identity, reason и адресные before/after |
| Баланс 100 → 110 → 100 | Итоговый diff пуст, история действий непуста | Обе причины и эффекты; итоговый diff как отдельная проверка |
| Reorg и возврат прежней ветки | Один block number не определяет актуальное состояние | Block hash, activation lifecycle, порядок версии canonical state |
| Повтор доставки | Простая сумма удваивает эффект | Стабильные IDs и логическое устранение повторов до расчёта |
| История приходит после live | Время вставки не является временем исполнения | Полный нативный порядок, pinned branch и доказанное coverage |
| После последней tx есть системное начисление | Конец последней транзакции не равен концу блока | Раздельные точки состояния after-tx и end-of-block |
| За последние 3 часа адрес не менялся | Из отсутствия строки нельзя узнать исходный баланс | Проверенный baseline; при его отсутствии — неизвестно, а не 0 |

Geth уже различает причины balance changes, в том числе withdrawals, transaction tips, gas purchase и gas return. Это подтверждает возможность исходного захвата, но не доказывает полноту интеграции других сетей или выбранного будущего commit. Источник: [Geth tracing hooks](https://github.com/ethereum/go-ethereum/blob/master/core/tracing/hooks.go), прочитан 2026-10-13.

## Требования к нормализованной записи

- Идентичность сети, блока и включения; нативный порядок действий.
- Причина действия, адреса, точные суммы в минимальных единицах; никаких float.
- Причинная связь с tx/call или системной операцией, статус rollback и итоговая применимость.
- Native before/after затронутых адресов. Для произвольного uint256 безопаснее before/after либо знак и модуль разности, а не непроверенное преобразование в signed int256.
- Отдельные lifecycle события для отмены каноничности и изменения финальности; их формат обсуждается в R07.
- Системная операция вне транзакции не получает выдуманный tx hash. Её предлагаемая единица публикации — отдельный SystemBalanceRecord.

## Проверка до NATS

Независимые native fixtures задают ожидаемые действия, множество изменившихся адресов и конечные значения. Проверка сверяет нормализованные данные, затем опубликованные bytes/поля в NATS. Проверяются нулевой суммарный эффект, revert, комиссии, системные изменения, reorg и повторная публикация.

Приняты строгие общие типы сообщений и разбиение слишком больших записей. Открыто: полный action schema, порядок для каждого клиента, точные payload/parts и объявление optional coverage. Способы обработки после публикации здесь не проектируются.

При выключенном сборе изменений вне транзакций нельзя утверждать полноту всей истории нативного баланса или требовать совпадения суммы только транзакционных изменений с балансом на конец блока. Полнота транзакций проверяется независимо. Операции вне транзакций не ограничиваются наградами майнеров: например, [Ethereum withdrawals](https://eips.ethereum.org/EIPS/eip-4895) — отдельные системные операции (источник проверен 2026-10-15).
