# E00-07 / E00-09 — пользовательский YAML и запуск истории

2026-10-21. IN_PROGRESS, только ТЗ. CFG-R1 закрыт D34/D35. Предложения отделены от принятых требований. Код/CLI/deployment не создаются.

## Принятые требования

- Единый интерфейс управления для всех пяти сетей; native реализация зависит от профиля сети.
- Пользователь меняет YAML выбранной сети и явно вызывает применение, например командой. Одного сохранения файла недостаточно. D34 уточняет D06: watcher и предложенный Kubernetes-aware launcher не приняты.
- После применения стартового блока выполняется догрузка этой сети, live продолжается. Другие сети и компоненты не перечитывают конфиг, не перезапускаются и не участвуют в управлении.
- Управление не зависит от Kubernetes/Docker API или конкретного оркестратора. Compose/Kubernetes — варианты размещения, а не обязательные зависимости приложения.
- Только стартовый блок применяется без рестарта (D35). Другие параметры требуют рестарта соответствующего процесса, не остальных сетей.
- Live и history — отдельные processes/pods по D23. Отсутствие Kubernetes-зависимости не разрешает запускать native replay внутри live процесса. Способ размещения отдельного исполнителя истории отделён от пользовательского интерфейса.
- Ручная команда N–M сохраняется: включительные границы, исходный диапазон активного задания неизменен, повторы и overlap разрешены.
- Первый запуск без стартового блока — последние три часа; вычисленное начало сохраняется для restart с диском. Потеря диска — новый run и ручная история по D27.
- Pending RocksDB payload не удаляется из-за изменения YAML. [Протокол ACK/recovery](ROCKSDB_DELIVERY_PROTOCOL.md) сохраняется.
- Пользователь выбирает поддержанные сети через .yml; неизвестный native adapter одним YAML не создаётся.

«Другие компоненты не знают» относится к управлению: они не получают управляющие команды и не должны изменяться. Данные догрузки штатно проходят существующий Adapter → Gateway → NATS; это не новая управляющая зависимость.

## Проект интерфейса

Пример, не утверждённое имя и не реализация: `extractor config apply --config ethereum.yml`. Для другой сети меняется профиль, а не смысл команды. Интерфейс передаёт запрос в контур одной сети; не вызывает Kubernetes API и не переконфигурирует Gateway/NATS.

Управляющая адресация/канал, формат результата/job_id и ошибки — CFG-S04. При недоступном отдельном исполнителе нельзя молча переходить к replay в live процессе. Точная семантика ошибки/retry ещё описывается; никакой новый глобальный scheduler или UI не вводится.

## YAML — проектная структура

Один файл на экземпляр сети; профиль совместен для live/history, writable каталоги разделены по owner. Точные поля/schema пока не утверждены.

| Группа | Назначение | Применение |
|---|---|---|
| schema_version | Версия конфигурации | Проверка совместимости |
| network/profile | Одна сеть и native adapter | Не hot-reload; смена сети не переносит старый store в другой профиль |
| history/start_block | Начало истории | Единственное изменяемое поле через apply без рестарта |
| native | Источник/state/replay параметры | Restart соответствующего процесса |
| delivery | Подключения Gateway/NATS по роли, references credentials | Restart; apply start_block их не меняет |
| storage | Каталоги RocksDB по owner | Restart; разные writers не открывают общий writable каталог |
| runtime | Рабочие настройки | Restart; TTL/квота pending не вводятся |

Рекомендация валидации: весь документ проверить до применения. Изменение других полей через hot apply отвергать с restart-required, без частичного применения. Invalid YAML не заменяет рабочую конфигурацию и не останавливает live. Детали — CFG-S04.

## CFG-R2 — открытые вопросы

### CFG-R2.1 — диапазон после применения

Пример: начало было 1000, стало 500, текущая высота при apply — 2000. Предложение: пройти 500–2000; верхнюю границу зафиксировать один раз. Новые блоки получает live. Повторы 1000–2000 разрешены D24; не нужны coverage registry или downstream queries.

Альтернатива: только добавленный участок 500–999, с отдельным рассмотрением ранее прерванной загрузки. Полный проход от нового начала до фиксированного head проще. Ответ ожидается.

### CFG-R2.2 — новая конфигурация при работающей догрузке

Предложение: прежняя догрузка завершает фиксированный диапазон; новая команда создаёт отдельное задание. Альтернатива: остановить прежнюю догрузку и заменить её новой, сохранив передачу всех уже pending данных до ACK. Ручные задания N–M не затрагиваются.

Очередь/параллелизм нескольких заданий определяется после выбора политики; отдельное задание не означает неограниченное число executors или shared writable native datadir. Ответ ожидается.

### CFG-R2.3 — удаление start_block

На первом старте отсутствие поля уже означает default три часа. При apply к работающей сети предложение: отсутствие поля сохраняет текущую durable границу и не запускает новый default. Для её изменения указать явный номер. Альтернатива: удаление поля заново вычисляет три часа от момента apply. Ответ ожидается.
