# E00-07 / E00-09 — конфигурация live и отдельной истории

2026-10-21. IN_PROGRESS, только ТЗ. D36 заменяет стартовую историю и догрузку через YAML/apply. Предыдущие CFG-R2 сняты; ответы на них больше не нужны.

## Принято D36

- Основной загрузчик получает только live данные. Начальной выгрузки «три часа» или «от start_block» нет.
- Историю загружает отдельный сервис на том же узле/хосте, что и native нода, по отдельной команде с явным диапазоном N–M.
- History и live — разные процессы; в Kubernetes разные pods, размещённые на том же узле, что и соответствующая нода. Приложение не вызывает Kubernetes/Docker API; размещение обеспечивает окружение.
- Интерфейс управления одинаков для Ethereum/BSC/Base/Arbitrum/Polygon; native реализация чтения/replay зависит от сети.
- Ручной N–M включителен; параметры задания фиксируются при запуске и сохраняются для restart с диском. Повторы/overlap допустимы.
- History не останавливает live и не переконфигурирует другие сети, Gateway или NATS. Данные идут по обычному пути публикации.
- Один writable native datadir/служебный RocksDB каталог не открывается несколькими writers. Историческому сервису необходим поддержанный native доступ/replay и нужные historical inputs; co-location сама по себе не гарантирует их наличие. Недоступный диапазон даёт ERROR, не усечение.
- Изменение YAML не запускает догрузку. Start_block/hot apply из D34/D35 больше не нужен. Остальные настройки по ранее принятому правилу применяются рестартом соответствующего процесса.
- Передача pending WAL до NATS ACK и очистка по [ROCKSDB_DELIVERY_PROTOCOL](ROCKSDB_DELIVERY_PROTOCOL.md) сохраняются.

## Единые команды — проектные имена

- Live: `extractor live --config <network.yml>`.
- History: `extractor history --config <network.yml> --from N --to M`.

Имена CLI пока проектные, не реализованные. Контракт history — один конечный проход N–M отдельным сервисом, а не команда изменения работающего live процесса. CLI не создаёт Kubernetes Jobs через API. Окружение запускает history process/pod на нужном узле; пользовательский контракт не привязан к способу размещения.

## YAML — draft

Один профиль сети может использоваться обеими ролями; writable каталоги/идентичности owner различаются. Выбор поддержанной сети и подключений через .yml сохраняется.

| Группа | Назначение |
|---|---|
| schema_version | Версия структуры и правила совместимости |
| network/profile | Поддержанная сеть и native adapter/profile |
| native | Подключение к native источнику, state/replay параметры |
| delivery | Подключения Gateway/NATS по роли, ссылки на credentials |
| storage | Изолированные RocksDB каталоги live/history/Gateway |
| runtime | Рабочие параметры соответствующего процесса |

Границы history задаются явной командой N–M; поля автоматической стартовой истории в live-конфиге отсутствуют. Точная schema, обязательность полей, CLI overrides, exit codes и правила invalid config ещё CFG-S04. Рекомендация: неизвестный/старый start_block отвергать понятной ошибкой, а не молча запускать историю или игнорировать намерение пользователя.

## CFG-R3 — один оставшийся вопрос о restart live

Live остановлен в 12:00, запущен в 12:10. Pending записи, уже сохранённые до остановки, отправляются автоматически по D26.

Открытый выбор касается **новых блоков за 12:00–12:10**, которых в WAL ещё нет: получать их автоматически при restart или только отдельной history-командой? Рекомендация в духе D36 — отдельной командой. До ответа это рекомендация, не принятое правило; прежний автоматический recovery нельзя молча расширять до любой истории или молча отменять для pending данных.

Native replay, необходимый для восстановления незакрытого ранее начатого capture batch, отдельно описывается в recovery; это не плановая загрузка нового исторического диапазона. CFG-S03 должен провести точную границу.
