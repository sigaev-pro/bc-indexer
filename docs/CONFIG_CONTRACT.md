## Принятые требования

- Один YAML описывает одну сеть. Пять исходных сетей: Ethereum, BSC, Base, Arbitrum One, Polygon PoS. Общий формат данных строго типизирован; native реализация учитывает сеть.
- Ноду запускает окружение штатной командой клиента. Встроенный адаптер получает YAML при запуске. Общий CLI не запускает ноду; Gateway/config check — отдельные команды.
- После синхронизации фиксируется каноническая голова H (высота/hash); новые live-наблюдения начинаются с H+1. Фиксация H согласована с native подпиской, без потери новых событий. Текущие reorg/finality сохраняются.
- Pending WAL восстанавливается и передаётся независимо от начала нового live-сбора. Восстановление конкретного ранее начатого capture не превращается в сканирование пропущенного периода.
- История, диапазоны N–M, history resume, поиск пропусков и внешняя сверка отложены D38. CFG-R2/CFG-R4 сняты; ответов не ожидаем. CFG-R3 закрыт D37.
- Настройки применяются рестартом соответствующего процесса. Нет watcher, apply-triggered history и зависимости приложения от Kubernetes/Docker API. Остальные сети не переконфигурируются.
- Writable состояние изолировано; один owner на каталог. Несовместимый профиль/сеть/состояние дают явную ошибку, не очистку WAL.
- Граница результата — нормализованные данные в NATS с подтверждением всех сообщений/частей batch. ClickHouse, бизнес-эффекты, дедупликация и поиск пропусков не критерии текущей приёмки.
