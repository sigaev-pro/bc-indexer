## Команды и роли

| Команда | Предлагаемый контракт |
|---|---|
| `extractor live --config network.yml` | Длительный live producer; продолжает передачу своего pending WAL, не сканирует пропуски |
| `extractor history --config network.yml --from N --to M` | Новый конечный history run, обе границы включены; отдельный процесс на хосте native ноды |
| `extractor history --config network.yml --resume RUN_ID` | Продолжение сохранённого run; диапазон читается из его состояния, `--from/--to` запрещены |
| `extractor gateway --config network.yml` | Gateway только указанной сети; свой каталог состояния и подключение к NATS |
| `extractor config check --config network.yml --role live` | Проверка структуры и требований выбранной роли (`live`, `history`, `gateway`), без записи состояния и без публикации |

Имя `extractor` — единая поставляемая CLI-точка входа; она выбирает установленный адаптер/исполняемый компонент профиля. Go/Rust native компоненты сохраняют собственные toolchains. CLI не скачивает клиенты, не создаёт pods и не вызывает API оркестратора. Команды выполняются на переднем плане; процессом управляет shell, Compose или Kubernetes.

`RUN_ID` — уже существующий идентификатор запуска из протокола доставки. Новая команда печатает его и путь состояния локально; специальное публичное startup-сообщение в NATS не добавляется. Pending payload и идентичности при resume сохраняются. Выбор новых команд/resume требует ответа CFG-R4.1.

## Общая структура YAML v1

Точные ниже имена — предложение. Все поля неизменны в течение жизни процесса; изменение файла применяется только рестартом соответствующей роли. Переменных `${...}`, произвольных CLI overrides и автоматического watcher нет. Пути разрешаются относительно YAML-файла, а не рабочей директории shell.

| Поле | Тип / обязательность | Значение и проверка |
|---|---|---|
| `schema_version` | integer, обязательно | Ровно `1`; неподдержанная версия — ошибка |
| `network.profile` | enum, обязательно | `ethereum-mainnet`, `bsc-mainnet`, `base-mainnet`, `arbitrum-one`, `polygon-pos-mainnet` |
| `native.source` | tagged union, для live/history | Профильный источник native capture/replay; схема ниже |
| `delivery.gateway_endpoint` | URI, для live/history | Адрес gRPC Gateway этой сети; не публичный RPC узла |
| `delivery.tls` | object, для подключения к Gateway | `mode: disabled` либо `mode: mutual` и пути `ca_file`, `cert_file`, `key_file`; отсутствие режима — ошибка |
| `storage.live_dir` | path, для live | Отдельный persistent RocksDB каталог |
| `storage.history_root` | path, для history | Каталог отдельных `RUN_ID`; live/Gateway сюда не пишут |
| `storage.gateway_dir` | path, для gateway | Отдельный persistent каталог Gateway |
| `gateway.listen` | endpoint, для gateway | Адрес gRPC listener |
| `gateway.tls` | object, для gateway | Те же явные режимы TLS и файловые ссылки; проверка клиентских сертификатов в mutual |
| `gateway.nats.servers` | непустой список URI, для gateway | Сейчас адрес одного инстанса; список не обещает HA |
| `gateway.nats.credentials_file` | path, optional | Файл credentials; секреты не помещаются в логи/ошибки |
| `gateway.nats.tls` | object, для gateway | Явный `mode: disabled`, `server` (CA) или `mutual` (CA, сертификат, ключ) |
| `runtime.log_level` | enum, optional | `debug`, `info`, `warn`, `error`; default `info` |

Одним файлом можно пользоваться для разных ролей. Валидатор проверяет структуру всего документа, обязательность и доступность локальных файлов — только выбранной роли. Producer не требует доступа к credentials NATS или каталогу Gateway. Профиль фиксирует chain identity и допустимые версии native компонентов; пользователь не переопределяет chain ID произвольной строкой. При подключении компоненты сверяют фактическую сеть с профилем и состоянием.

`native.source` не является нетипизированным словарём: discriminator `kind` выбирает закрытую схему адаптера. Общие поля — `kind` и `instance` (идентификатор локальной native ноды). Настройки IPC/observer, historical inputs, snapshot/replay datadir задаются профильной схемой. **Остаток CFG-S04:** выписать точные поля каждой ветви по уже выбранным клиентам; нельзя выдавать общий `rpc_url` за замену native capture. До этого YAML-контракт не считается завершённым.

Subjects, Protobuf envelope и разбиение сообщений задаёт общий протокол публикации, а не свободная строка в YAML. Численные параметры buffers/chunk limits/concurrency нужно согласовать с E00-04 и ограничениями транспорта; произвольных чисел в этом предложении нет. Каталог RocksDB — служебное состояние, не native datadir. Источники replay не могут совместно открывать datadir как writers.

## Диапазоны и restart

- N/M — неотрицательные десятичные целые, без дробей, знаков и экспоненты; N ≤ M. Проверяются без потери точности floating-point, дополнительно по диапазону native высот профиля.
- Для history обязательны обе границы либо один `--resume`. В live границы, `start_block`, default lookback и `apply` не поддерживаются.
- Предложение: M выше текущего доступного блока — явная ошибка; history не ждёт будущих блоков и не превращается в live. Недоступный архив/replay также ошибка, не сокращение диапазона. Проверка до старта не гарантирует дальнейшую доступность источника: runtime-сбой сохраняет уже записанное состояние.
- Live использует стабильный `live_dir`; history — отдельный каталог на run. Один owner держит эксклюзивную блокировку своего состояния. Второй writer завершается с ошибкой; совпавший диапазон другого run допустим.
- Resume проверяет сохранённые network/profile, роль, N/M и версию протокола. Несовместимые изменения отвергаются без очистки WAL. Смена endpoint/credentials возможна при сохранении идентичности сети и delivery peer согласно протоколу восстановления.
- History считается успешно завершённым после NATS PubAck всех подготовленных сообщений/частей диапазона и durable фиксации ACK; порядок cleanup определяется протоколом RocksDB. Resume завершённого run возвращает успех без новой выгрузки. Новая выгрузка требует нового run.

## Валидация и завершение процесса

До открытия writable состояния проверяются синтаксис, дубли ключей, неизвестные поля, типы, роль, сочетания аргументов, пути и идентичность профиля. Ошибка содержит путь поля и причину, без секретов. Старые поля истории отвергаются с пояснением про отдельную команду. Неверный файл не частично применяется. Ошибка одного процесса не останавливает другие сети.

Предлагаемые exit codes: `0` — успешное завершение; `2` — CLI/YAML; `3` — несовместимое или занятое состояние; `4` — недоступные native inputs/неподдержанный профиль; `5` — невосстановимая ошибка исполнения/записи. SIGINT/SIGTERM прекращает новые чтения, сохраняет имеющееся durable состояние и завершает процесс соответственно с `130`/`143`; прерванный history не считается успешно загруженным. Неподтверждённые данные не удаляются. Временная недоступность NATS не завершает сбор по таймеру и не вызывает очистку WAL.

`config check` проверяет конфигурацию, а не полноту блока, доступность всей истории или доставку в NATS. Он не создаёт stream, служебные DB или run. Пробы сети выполняются при запуске соответствующей роли; ошибка подключения не трактуется как успешная проверка работоспособности.

## Отложенный раунд CFG-R4 — ответы не требуются (D38)

1. **Повтор history-команды.** Предложение: `--from N --to M` всегда создаёт новый run; продолжение после остановки — `--resume RUN_ID` с тем же YAML. Так повторная выгрузка и восстановление не путаются. Альтернатива: команда с теми же N–M сама продолжает прежний незаконченный run, а для нового нужна дополнительная опция.
2. **Верхняя граница в будущем.** Предложение: если M ещё не существует, вернуть ошибку. Альтернатива: держать history-процесс запущенным до появления M. Это влияет только на явно запрошенный диапазон, не на live.
