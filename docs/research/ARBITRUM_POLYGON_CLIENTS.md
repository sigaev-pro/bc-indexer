# Arbitrum One и Polygon PoS: нативные источники данных

Дата проверки: 2026-10-15. Этап: исследование исходников; сборка, запуск узлов и измерение полноты/производительности **не выполнены**. Граница проекта: нормализованные типизированные сообщения → NATS. RPC сборщика для извлечения транзакций/трейсов не предлагается; служебные подключения самих клиентов к L1/Heimdall — отдельная зависимость клиента.

## Вывод для архитектуры

| Сеть | Рекомендуемый исходный клиент | Стек адаптера | Нативная точка интеграции | Главный непроверенный риск |
|---|---|---|---|---|
| Arbitrum One, chain ID 42161 | OffchainLabs Nitro, Go execution backend с его собственным go-ethereum | Go; сборка Nitro также требует Rust/C/C++/WASM-инструменты | Встроенный live tracer + наблюдение canonical chain; отдельное нативное повторное исполнение истории | Live tracer повторно исполняет блок; Classic до Nitro требует отдельного исторического профиля; Stylus требует собственных hooks |
| Polygon PoS, chain ID 137 | Bor + Heimdall-v2 | Go; C toolchain для сборки | Встроенный live tracer Bor + chain events + специальные state-sync пути | Трейсер выключает параллельный V2 execution; до/после Madhugiri state sync представлен по-разному |

Это **рекомендация по результатам чтения исходников**, не утверждение о готовой интеграции. Единый Go-модуль можно переиспользовать на уровне нормализации/сериализации, но ABI hooks и зависимости клиентов должны оставаться отдельными: у Nitro собственный форк go-ethereum, у Bor собственные изменения. Один общий бинарник с подменой сети не предлагается.

## Arbitrum One: подтверждённые точки захвата

1. Nitro умеет подключать live tracer; конфигурация сама маркирует эту возможность experimental/costly. В `appendBlock` наличие `GetVMConfig().Tracer` меняет путь с записи уже исполненного блока на `InsertChain`, то есть **повторное исполнение полного блока ради live tracing**. Нельзя обещать бесплатный callback на уже готовом результате. [Конфигурация](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/execution/gethexec/node.go#L234-L247), [appendBlock](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/execution/gethexec/executionengine.go#L1373-L1394).
2. Форк go-ethereum предоставляет tx/call/state hooks и собственный `CaptureStylusHostio`. Через tx start/end нужно связывать transaction с receipt/error, через enter/exit — дерево вызовов, через balance/storage/code/nonce hooks — изменения, через receipt — итоговые сохранённые logs. Это предлагаемый адаптер поверх существующих hooks; точная полнота проверяется POC. [Hooks](https://github.com/OffchainLabs/go-ethereum/blob/5eee8f546e7602b7deeef7909f291bbebc77e233/core/tracing/hooks.go).
3. Не ограничиваться стандартными Ethereum tx types. В pinned исходнике есть `ArbitrumDepositTx=0x64`, `Unsigned=0x65`, `Contract=0x66`, `Retry=0x68`, `SubmitRetryable=0x69`, `Internal=0x6a`, `Legacy=0x78`. В начале блока создаётся внутренний StartBlock tx. В адаптере нужны исходный тип, полный native payload и типизированные расширения, а не отбрасывание неизвестного Ethereum decoder типа. [Типы](https://github.com/OffchainLabs/go-ethereum/blob/5eee8f546e7602b7deeef7909f291bbebc77e233/core/types/transaction.go#L48-L54), [StartBlock](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/arbos/block_processor.go#L384-L399).
4. Deposit/Internal/SubmitRetryable имеют special execution paths до/вместо обычного EVM. Nitro вручную формирует trace frames и выполняет mint/escrow/refunds. Сбор только EVM opcodes потеряет часть действий. Included failed tx сохраняется с failed receipt; отклонённая до включения операция не должна выдаваться за included transaction. [Tx processor](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/arbos/tx_processor.go#L156-L277), [retryable accounting](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/arbos/tx_processor.go#L276-L565).
5. Stylus исполняет WASM, поэтому нельзя назвать все его внутренние шаги EVM opcodes. Native `stylusTracer` принимает HostIO name/args/outs/ink и вложенные вызовы; `CaptureEVMTraceForHostio` адаптирует отдельные взаимодействия, а не доказывает полное совпадение WASM и EVM trace. Рекомендация: сохранять общий call/result/state слой, engine kind и типизированные Stylus детали; не требовать полный WASM instruction trace без отдельного решения. [Stylus tracer](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/execution/gethexec/stylus_tracer.go#L29-L87), [HostIO bridge](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/arbos/util/tracing.go#L136).
6. Hooks исполнения сами по себе не равны решению о canonical inclusion. Внутренние `SubscribeChainEvent`/`SubscribeChainHeadEvent` и Nitro `ExecutionEngine.Reorg` — точки наблюдения принятия/смены цепочки. Рекомендация: держать execution result по block hash и публиковать отдельно canonical/reorg metadata; окончательное место durable hook выбрать после проверки порядка commit/events. [Подписки](https://github.com/OffchainLabs/go-ethereum/blob/5eee8f546e7602b7deeef7909f291bbebc77e233/core/blockchain_reader.go#L559-L573), [Reorg](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/execution/gethexec/executionengine.go#L578-L644).

### История и зависимости Arbitrum

- Arbitrum One Nitro genesis — **22 207 817**. История ниже этого номера относится к Classic; один текущий Nitro replay backend не является доказательством покрытия с первого блока. Nitro содержит Classic redirect, но RPC redirect не соответствует выбранному нативному сбору. Нужен отдельный исследованный Classic reader/replayer либо явно отмеченный неподдержанный диапазон; молча обрезать N–M нельзя. Дополнение основного агента: проверен кандидат Classic `v1.4.7` / `dd4595f894b52c73a293a0c4bce9411afb12da12`; найден native trace cursor, но полный capture/исторический архив и сборка ещё не проверены (подробнее ниже). [Pinned chain info](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/cmd/chaininfo/arbitrum_chain_info.json#L1-L42), [Classic redirect integration](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/execution/gethexec/node.go#L566-L581).
- Archive retention отключён по умолчанию. В path archive ненулевой `StateHistory` ограничивает сохранённую историю. Наличие тела старого блока и receipts не гарантирует parent state, необходимый для восстановления calls/state changes. В проверенном state accessor fallback ограничен `reexecLimit=128` и возвращает ошибку при отсутствии состояния. Исторический worker должен проверять доступность состояния/блоков до обещания успешного диапазона. [Caching config](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/execution/gethexec/blockchain.go#L30-L168), [State accessor](https://github.com/OffchainLabs/go-ethereum/blob/5eee8f546e7602b7deeef7909f291bbebc77e233/eth/state_accessor.go#L47-L137).
- Для собственного Nitro узла остаются L1 Ethereum connection, получение blob data через beacon endpoint и sequencer feed для быстрого live. Отсутствие RPC в extraction hot path не отменяет эти зависимости native node. Это не зависимость от процесса Ethereum extractor: можно использовать отдельно заданные L1 endpoints/узлы. [Nitro startup](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/cmd/nitro/nitro.go#L316-L330), [network configuration](https://github.com/OffchainLabs/nitro/blob/70fa99a6e711f09eedd96a907290c3df0f3bcf7d/cmd/nitro/config/config.go#L425-L451).

### Classic: дополнение source audit основного агента

Официальный репозиторий описывает себя как старый Classic stack. Проверенный release — [v1.4.7](https://github.com/OffchainLabs/arbitrum-classic/releases/tag/v1.4.7), commit `dd4595f894b52c73a293a0c4bce9411afb12da12`. Это кандидат отдельного исторического backend, не полноценная подтверждённая поддержка. [README](https://github.com/OffchainLabs/arbitrum-classic/blob/dd4595f894b52c73a293a0c4bce9411afb12da12/README.md).

Состав — Go wrapper + C++ AVM. Модуль arb-rpc-node содержит директиву `go 1.13`, а Dockerfile использует отдельный cpp-base и CMake: директива не фиксирует фактическую версию компилятора образа. Native ArbCore предоставляет GetLogs, GetExecutionCursor, AdvanceExecutionCursorWithTracing и GetExecutionCursorAtEndOfBlock. Рекомендация — вызывать такие внутренние интерфейсы из встроенного historical adapter, не обращаться к RPC trace endpoint. [Module](https://github.com/OffchainLabs/arbitrum-classic/blob/dd4595f894b52c73a293a0c4bce9411afb12da12/packages/arb-rpc-node/go.mod), [build](https://github.com/OffchainLabs/arbitrum-classic/blob/dd4595f894b52c73a293a0c4bce9411afb12da12/packages/arb-node.Dockerfile), [ArbCore](https://github.com/OffchainLabs/arbitrum-classic/blob/dd4595f894b52c73a293a0c4bce9411afb12da12/packages/arb-avm-cpp/cmachine/arbcore.go#L379).

Наличие trace cursor не решает полный state diff: текущий trace frontend разрешает лишь trace/deletedContracts, а поле StateDiff не является реализованным общим diff. Следовательно, для всех требуемых before/after/actions нужно отдельно исследовать AVM state/ArbOS instrumentation и доступность архива. Этот пробел остаётся открытым в E00-15/AP-06. [Trace implementation](https://github.com/OffchainLabs/arbitrum-classic/blob/dd4595f894b52c73a293a0c4bce9411afb12da12/packages/arb-rpc-node/web3/trace.go#L276), [native trace representation](https://github.com/OffchainLabs/arbitrum-classic/blob/dd4595f894b52c73a293a0c4bce9411afb12da12/packages/arb-evm/evm/tracing.go).

## Polygon PoS: подтверждённые точки захвата

1. Bor имеет `LiveDirectory.Register` для нативного tracer и transaction/call/state hooks. Рекомендация: встроить Go адаптер в pinned Bor, не опрашивать `debug_trace*`. Подключение live tracer — compile-time registration плюс конфигурация; не обещается ABI-стабильный динамический plugin. [Live registry](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/eth/tracers/live.go#L27-L55), [hooks](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/tracing/hooks.go).
2. **Параллельное исполнение V2 не поддерживает общий tracer**: при non-nil tracer код возвращает `errV2TracerUnsupported`, чтобы fallback пошёл V1. Производительность Bor без tracer нельзя переносить в оценку extractor. [V2 guard](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/parallel_state_processor.go#L1088-L1093).
3. До Madhugiri state-sync не входил в body transactions. Есть отдельный Bor receipt и derived hash `keccak256(BorReceiptKey(number, blockHash))`; такой hash нельзя считать hash подписанного Ethereum envelope. Нужны отдельный тип происхождения и отдельный счётчик native synthetic records, чтобы проверка полноты body tx не давала ложных расхождений. [Bor receipt](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/types/bor_receipt.go#L18-L50), [rawdb receipt](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/rawdb/bor_receipt.go#L79-L109).
4. После Madhugiri `StateSyncTxType=0x7f` — реальная последняя транзакция body. `Finalize` сверяет её hash с данными Heimdall и добавляет receipt. Её нельзя исключить под формулировкой «изменения вне транзакций необязательны». В pinned mainnet config Madhugiri — блок **80 084 800**, chain ID 137. [Тип](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/types/transaction.go#L48-L55), [Finalize](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/consensus/bor/bor.go#L1286-L1312), [Mainnet config](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/params/config.go#L410-L436).
5. Обычный tx loop пропускает StateSyncTx, но processor вызывает отдельные `OnTxStart/OnTxEnd` вокруг `Finalize`. Hooks wrapper создаёт synthetic root frame вокруг независимых state-sync EVM calls. Подсчёт только вызовов обычного ApplyTransaction потеряет эту транзакцию. [State processor](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/state_processor.go#L156-L195).
6. **Известная неоднозначность upstream**: комментарий `Finalize` признаёт, что изменения code из block-alloc upgrades могут попадать внутрь окна state-sync tx. Это нельзя безусловно выдавать как изменения этой транзакции. POC должен выявить такие блоки; адаптеру может потребоваться небольшой patch разделения scopes. [Source comment](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/consensus/bor/bor.go#L1270-L1278).
7. Bor публикует internal chain/head/removed-log события; `Chain2HeadEvent` содержит old/new chains и вид head/fork/reorg. Использовать это вместе с результатом commit, не объявлять блок canonical в момент одного `OnBlockEnd`. [Event model](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/bor_events.go#L12-L23), [reorg path](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/blockchain.go#L4575-L4584), [subscriptions](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/core/blockchain_reader.go#L930-L948).

### История и зависимости Polygon

- Bor зависит от Heimdall данных state sync/consensus: `Finalize` вызывает `CommitStates`, а тот получает `StateSyncEvents`. Два отдельных контейнера/процесса Bor и Heimdall образуют **один профиль сети**, не две сети extractor. Heimdall-v2 — Go/Cosmos SDK/CometBFT, со своими Polygon forks. Собственные tx Heimdall не следует молча смешивать с Polygon EVM tx; здесь исследуется Polygon PoS execution chain. [CommitStates](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/consensus/bor/bor.go#L2009-L2077), [Heimdall README](https://github.com/0xPolygon/heimdall-v2/blob/ced0710a3f6e269b8d5e996eb7d2b740fd9f80c5/README.md), [actual dependencies](https://github.com/0xPolygon/heimdall-v2/blob/ced0710a3f6e269b8d5e996eb7d2b740fd9f80c5/go.mod#L309-L323).
- Историческое повторное исполнение требует parent state, body/receipts и исторических consensus/state-sync данных. Bor state accessor явно ограничивает количество reexecuted ancestors и ошибается, если нужный state отсутствует. «Загрузить старый body» не равно «восстановить все детали tx». Нативный history worker должен иметь отдельный execution/state context и ресурсный бюджет, не вызывать SetHead на live узле. [State accessor](https://github.com/0xPolygon/bor/blob/9c445ef603e71469e1c176d8e57e7cf94864ade7/eth/state_accessor.go#L41-L131). Последнее предложение — проектная рекомендация.
- Совместимость выбранной пары Bor/Heimdall, replay старых Heimdall эпох и доступность state-sync records на всём диапазоне пока **не проверены**. Это gate для обещания истории от первого блока, а не причина исключать текущие Polygon tx.
